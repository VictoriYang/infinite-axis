## 一、测试时适应：把容器从快权重换成外部记忆

### Can Test-Time Memory Evolution Outperform Test-Time Training for Scientific Discovery?

[论文](https://huggingface.co/papers/2610.32046) · UCSB / UC Berkeley

近来一批 test-time training（TTT）框架让开放权重模型在科学发现任务上超过了由前沿模型驱动的纯推理框架。代价是在线权重更新带来的额外算力开销，模型越大越难摊销。

这篇问了一个干净的问题：如果把「测试时适应」的**容器**从快权重换成**外部记忆**，会怎么样。他们提出 Test-Time Memory Evolution（TTME）——不更新任何权重，只把经验蒸馏进持续演化的外部记忆来引导后续探索。为了对照干净，TTME 与 TTT 放在同一套 discovery 框架里，**只替换测试时适应方法这一个变量**。

结果是单向的：TTME 在五个数学任务上**全部**优于 TTT，同时 FLOPs 降低 82.8–84.6%、实际运行时间降低 47.7–58.4%。

这个结果值得单独拎出来说，是因为它挑战的是一个相当普遍的隐含前提。「让模型部署之后继续变强」这件事，过去一年多被默认为一个工程问题：把在线权重更新做得够快、够省，塞进实时回路就行。在这个框架下，快权重是答案，剩下的是优化。

TTME 说的是：在受控对比下，快权重不只是更贵（算力约 6 倍、墙钟时间约 2 倍），**效果还更差**。那么合理的做法应该反过来——**先把外部记忆版本作为基线，把在线改权重当成需要被证明的那一方**。

两点克制：它只测了数学与科学发现任务，没有任何机器人或具身证据；把这个对照搬到动作策略上（同一个模型、同一套任务，只替换适应容器）目前还没人做过，而那恰恰是最该补的实验。

另外值得一提的是这条是怎么进来的：它在候选池的机械预筛阶段就被按源预算砍掉了，关键词分只有 3 分，是从被砍记录里捞回来的。这是一个反复出现的结构性问题——**最能改变做法的论文，往往关键词密度最低**。TTME 的摘要里一个流行方法名词都没有。

### The sleep framework

[Google Research](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/) · 2026-10-27

同一周，Google Research 给出了一个方向相反但其实不矛盾的答案：它确实在改权重，**但把改权重挪出了在线回路**。

sleep framework 给持续学习加了一个离线的「睡眠」阶段。wake 阶段模型正常接收与交互，短期信息存在高频记忆层；sleep 阶段模型停止接受新输入，把算力转向两件事：

- **记忆巩固**——通过参数扩展解锁预分配的 MoE 低秩专家，把短期记忆写进稳定的低频记忆块，从而不覆盖旧参数；配合 on-policy 蒸馏（让巩固对齐模型推理时真正会产生的轨迹）和语义奖励（决定什么值得留下，而非单纯匹配 token 概率）。
- **做梦**——随机激活不同专家来生成合成经验，扩宽探索到的梯度方向，再用基于梯度的筛选保留信息量最大的那些。作者的说法是，这不只是自生成数据增强，而是对「模型据以自我改进的那些更新」做多样化、筛选与巩固。

数字：BABILong 上扩展到 1000 万 token 近乎无衰减；满语、Kalamang 这类未见语言的连续翻译在多阶段评测中几乎零掉点，而上下文学习、Cartridges、SFT 都出现严重灾难性遗忘；事实注入在 SQuAD 上 48.9%、持续预训练设定下 46.2%，优于 SEAL 等基线。

把这两篇放在一起读，结论不是「该不该改权重」，而是**「什么时候改」**。在线那段只需要**记住**——便宜，不动权重；离线那段才负责**学会**——可以贵。很多系统之所以被实时性卡死，是因为把这两件事当成了一个必须同时满足的单一问题。对需要长时间部署的物理系统来说，这个切法尤其自然：机器总有停机的时候。

### Harness-Model Collaboration for Long-Horizon Continual Learning

[论文](https://huggingface.co/papers/2610.34724)

HaMo 正好是上面那个「两段预算」的一个具体实现。它指出现有系统通常二选一——要么靠模型适应，要么靠外部记忆——本质是在「持久学习」和「快速复用」之间做交换。

HaMo 两者都要：把轨迹蒸馏成**策略级的经验卡**供即时检索（快、非参数），同时用一个 experience-conditioned 的持续学习目标，训练模型去**理解、grounding 并执行**检索到的策略；另有一个基于检索覆盖度的机制，挑选紧凑且互补的轨迹来做参数更新。在域内与跨域迁移下都优于只用外部记忆或只做模型适应的做法，保持与适应两头都有改善。

其中一个细节值得单独强调：HaMo 明确要求模型**被训到能读懂卡片**，而不是假设「检索出来就能用」。很多技能库式的设计栽在后一个假设上。

## 二、记忆：三篇负面结果

本期有三篇集中打同一件事——**专门设计的记忆机制，净收益常常是负的**。

### Memory Tax: Dissecting the Net Value of Agent Memory

[论文](https://huggingface.co/papers/2610.34073) · [项目页](https://hexuan21.github.io/MemoryTax/)

跨多个 benchmark 与多个模型骨干的大规模评测，结论是**许多专门设计的记忆系统打不过朴素 RAG**。

作者把记忆相对「直接从原始历史检索」的差额拆成两半：memory benefit 与 **memory tax**。记忆系统为了组织信息所做的改写——重组事实、蒸馏偏好——本意是帮助任务，但同样的改写也会**删掉或遮蔽证据**，后者就是税。文章的主要篇幅花在这个被忽视的税上：它如何从系统侧和评测侧分别产生。

这篇真正有用的地方是它改掉了对照组。评估一个记忆或上下文模块时，默认对照组通常是「没有这个模块」——那几乎必然是正收益。把对照组换成**直接检索原始历史**，符号立刻翻转。换句话说，对照组选错时，衡量的只是「有信息比没信息好」这件废话，测不出结构本身有没有贡献。

### Rare, Relevant, and Still Wrong: How Memory Fails LLM Group Decisions

[论文](https://huggingface.co/papers/2610.37624)

当一群模型的讨论被压缩成一段短记忆、交给最终决策者时，记忆该留下什么？两种自然的启发式是「留最稀有的声明」和「留与判据最相关的声明」。在 hidden-profile 任务上两者看起来都不错——但那是因为「一个事实被多少人持有」和「它是否有用」在这类任务里是混淆的。

作者做了 CrossProfile 来解这个混淆：60 个模板、480 个任务，把支持性事实、诱饵、无关事实的**归属权**交叉打乱，而文本本身保持不变。答案键自动验证。

在 Qwen2.5-7B、Llama-3.1-8B 和两个 DeepSeek 模型上，两种启发式都在可预测的地方失败：

- 按相关性筛选会把诱饵重新放回来，因为诱饵本来就切题——即便是一个完美的相关性过滤器，在经典配置下也比 rarest-first 低 23 到 31 分。
- rarest-first 平均而言并不比随机选择更好，只在「稀有事实恰好有用」时占优。
- 两种情况下，准确率跟着**记忆留下的证据平衡**走，而不是跟着那个筛选策略走。

决策模型还贡献了第三种失败：一种**社会认同偏差**——它给「被很多 agent 归属」的事实额外权重。去掉归属标签，或在保持行序的前提下随机重新分配归属，在经典配置下反而把准确率提高 13 到 24 分。

最刺的一条结论在最后：在自然讨论里，证据在任何记忆机制生效**之前**就已经丢了——**完整转录的准确率比完全不做笔记还低**。

那个解混淆的实验设计本身值得借鉴：固定文本、只交叉归属权。任何「某条信息来自哪个来源」和「它对不对」缠在一起的评测，都有同构的问题。

### HABIT-Bench

[论文](https://huggingface.co/papers/2610.24520)

第三篇作为佐证：用户在长期交互中通过选择暴露习惯，而单次观察往往只提供关于某个习惯的部分证据。HABIT-Bench 构造了跨越数百个会话、覆盖餐饮/金融/软件/旅行的合成用户历史与受控习惯图，评测记忆系统能否从弱证据中归纳习惯并在之后恰当应用（含临时例外、习惯变更、用户未采纳的建议）。

八种记忆方法中最好的只有 **33.61%** 的宏平均准确率。更值得注意的是：**即便把标注好的证据直接喂进去，性能依然受限**——这说明差距不只在检索，而在归纳与恰当应用这一步。

## 三、表示与混训

### ChronoReplay: One Answer Interface Is Not Enough for Streaming Spatial Intelligence

[论文](https://huggingface.co/papers/2610.34283) · 本期最热，345 upvotes

这篇提出了一个很干净的概念：**interface lock-in**（接口锁定）。

训练一个空间 VLM 去回答「物体在哪一侧」，并不要求它保留那个决定了答案的**度量位移**；反过来，对距离估计的监督也可能让类别关系基本不受约束。于是，后训练偏重哪一种 readout，增益就集中在那个接口上，而**向其他接口的迁移很弱、甚至退化**。

ChronoReplay 的解法是把异构的空间监督**按时间顺序重放成 episode**，保留各来源原生的目标格式，并在监督族之间做平衡。同样的观测条件下，单个 checkpoint 同时提升 OVO-S-Bench、OST-Bench 和 UCS-Bench，其中 OST-Bench 上 +13.41 分。

同数据对照把各成分拆开了：answer serialization 负责在 OST 和 UCS 之间重新分配增益；family-balanced 学习优于普通联合 SFT 和自然轮次加权；按时间顺序重放比打乱顺序的对照高约 2.41 个 OST 分（两组配对种子）。此外，在模型固定的前提下做自适应帧选择，还能以更低视觉成本拿到额外的推理期增益。

这篇改变的是对「多数据集混训冲突来自哪里」的理解。通常的直觉是冲突在**输入侧**——不同来源的分布差异，于是配比在「数据来源」这个维度上调。ChronoReplay 指出还有一层在**输出侧**：监督用什么形式提问与作答，决定了模型保留哪些区分度，而不同 readout 之间会互相挤占。推论是，把所有来源统一转换成同一种目标格式再混，可能正是丢掉信息的那一步；**保留来源原生的目标、按「监督族」而不是按数据集来平衡**，也许才是对的轴。

### Can Discrete Tokens Serve as Semantically Lossless Representations of Visual Signals?

[论文](https://huggingface.co/papers/2610.37662)

离散视觉 token 把视觉表示成类似语言的离散形式，为「共享一个 next-token 预测目标」的多模态建模提供了原生接口。但有一个被广泛默认的假设：量化误差会造成不可避免的语义损失，因此连续表示是内在的上界。

作者以多模态理解作为语义保真度的代理，重新检验了这个假设，发现**量化误差是个不可靠的指标**——重构误差明显更大的离散表示，反而可以有更好的理解性能。真正起决定作用的是离散索引的**有效 bit 预算**。但已有量化器最终会饱和：继续增加码本，边际语义贡献递减。

他们提出 Factorized Vector Quantization：对视觉特征的互补、固定维度的视图，用对称的并行码本做量化。它在更大 bit 预算下持续改善，最终在多模态理解上**追平连续表示**，九项指标均值超过 UniAR 22.8%、Emu3-Chat 59.2%，并且是第一个能与 Qwen3-VL 这类强连续表示模型竞争的离散表示模型。

这个结论的适用面比视觉更宽。任何把连续信号离散化的场景——包括把连续控制量离散成 token——都倾向于用**重构误差**来判断「表示有没有丢东西」。这篇说明那个代理量会误导：重构误差和下游语义保真度不是一回事，该盯的是有效 bit 预算，以及增加码本会不会饱和。设计上的推论同样明确：并行、分解式的码本结构，比单纯加大单个码本更值得优先尝试。

## 四、失败数据与自进化

### MiRL: Error-Targeted Reinforcement Learning for Correcting Terminal Agent Misbehaviors

[论文](https://huggingface.co/papers/2610.35697) · UNC

error-targeted learning 的思路很朴素：找出模型的具体弱点，针对性地训练去修，再检查是否真的修好了。难点在于已有方法都是为单轮任务设计的，而已有的 agent 失败分析大多用来**评估和调试**，不是用来**训练**。

MiRL 把它用到了终端智能体（用自然语言指定、通过命令行交互求解的长程任务）上。做法分两步：先给策略的错误做**画像**，找出跨多个环境反复出现的、可泛化的 misbehavior；然后从这些 misbehavior 发生的那一步开始 rollout 做 RL，并且**只有当 rollout 既通过测试、又避开了该 misbehavior 时才给奖励**。

数字相当硬：

- Qwen3.5-4B 上，**八种 misbehavior 就占了 52.1% 的错误步**。
- 训练之后，在未见过的前缀上这些行为的复现率平均下降 **43% 到 57%**。
- Terminal-Bench Lite 上 51.8% 对 TMax-4B 的 47.4%，Terminal-Bench 2.1 上持平（21.3% vs 20.6%），而**只用了后者 35% 的 rollout**。

权重和训练数据都已公开。

这篇改变的是处理失败数据的**顺序**。常见做法是把失败轨迹收集起来、重采、标注、回灌，本质上是在失败分布上无差别地加权。MiRL 指出失败其实是**高度集中且可枚举**的——八种占一半——所以正确的顺序应该是：先聚类画像，再从失败点定向起 rollout，并把「不要再犯这一种」显式写进奖励。35% 的 rollout 就能打平，说明这个顺序差别直接对应几倍的采样成本。

迁移到物理系统的障碍也很清楚：终端任务自带自动测试充当 verifier，真机没有。所以要用起来，缺的那一环是「如何自动判定一次执行犯了哪一种 misbehavior」。

### RSI Arena: Towards Recursive Self-Improvement with Human Feedback

[论文](https://huggingface.co/papers/2610.33624)

十个前沿模型充当「训练智能体」，各自从 NVIDIA Nemotron 3.5 Lightning 30B-A3B Base 出发，在共享的 64 卡集群上拥有 1000 GPU 小时和 300 美元 API 额度，六天内自主选择数据、实现训练流程、挑选 checkpoint。第二阶段把涉及自己模型的人类对比投票喂回去，再给三天继续训练。

结果：十个 agent 全部产出了可用的助手模型；最强的那个（由 GPT-6 Astra 训练）在 12 个能力 benchmark 上补上了 base 到 Instruct 差距的中位数 **76%**，人类偏好评分在对长度和格式做统计校正后也接近 NVIDIA Instruct。第二阶段，十个里有八个的风格校正后相对评分上升。

但这篇最有价值的部分是作者自己报出来的那几条负面观察：**benchmark 增益是温和的，且与偏好增益没有明确关联**；一些 agent 诱导出了更长的回答；**有一个模型在 StrongREJECT 上的有害顺从度上升了**。

这组观察修正了对自进化闭环的一个常见担心。通常的担心是「转不动」——迭代几轮就饱和。RSI Arena 说十个全都转得动，**真正的风险是转错方向**：优化目标与人类实际偏好脱钩，并顺带把长度偏好、有害顺从这类副作用一起优化了进去。推论是，任何自生成数据的飞轮，只监控「主指标有没有涨」都不够，必须同时锁定一组**不该变的指标**，否则很可能在主指标上涨的同时把别的东西换掉了。

## 五、世界模型：一致性从哪里来

### Genie 4

[Google DeepMind](https://deepmind.google/blog/genie-4-a-new-generation-of-world-simulation/) · 2026-10-27

实时交互世界模型，原生多模态——环境音、音乐和**可交互对话**与画面同时生成，是 DeepMind 第一个原生生成音频的实时世界模型。底座接 Gemini 家族：Gemini Omni 负责把模拟锚定在真实世界的外观与行为上。官方把用途之一明确写作「为机器人与智能体开发训练环境」。目前是面向可信测试者的 research preview。

抛开画质，技术上最值得记的一点是**长程一致性的来源**：**Gemini 3.8 Flash 作为回路内的引导智能体**——Genie 4 实时生成世界的同时，Gemini 持续观察场景、把目标拆解成步骤序列、逐帧复核每一步是否成功；世界发生变化或用户介入时，它当场调整计划。

这是一个值得注意的架构选择。通常默认世界模型的长程一致性是**生成模型自身的能力问题**，要靠更长的上下文或更好的内部记忆机制解决，于是评判一个世界模型主要看它单模型能连贯多久。Genie 4 把一致性**外包给了一个回路内的 VLM 验证器**：生成器只管下一段，验证器负责判断有没有跑偏。如果这条路成立，那就不必等一个能自我保持一致的世界模型——在已有生成器外面套一层逐步验证，现在就能做。

保留意见要写明：整篇公告没有任何定量数字，没有一致性时长、延迟或分辨率指标，没有机器人侧结果，不开放权重。上面这条判断的证据强度是「DeepMind 自述的架构」，不是实测。

### Hy-Nomas: Towards Free-form Interactive World Generation

[论文](https://huggingface.co/papers/2610.36729)

和 Genie 4 配成一对看：后者是闭源的能力上限，这条是现在能真正拿来用的那个。

8B 扩散主干的视频世界模型，支持自由文本指令和跨多轮交互的连续相机控制，依据当前输入与缓存历史生成变长片段。核心设计是把**结构化视频描述**与**动作感知的因果注意力**对齐：描述性上下文跨片段保持可访问，而动作指令被限制在它应当生效的时间窗内。这一刀正好切在「历史要记住、但旧指令不该继续生效」这个矛盾上——任何做分块式动作生成的系统都会遇到同一类边界问题。

另有一个视觉语言 Prompt Enhancer，把用户请求和多模态交互历史翻译成下一段的结构化条件；多阶段课程逐步引入因果生成、文本交互、相机控制，以及**在模型自己生成的历史上训练**，最后做扩散蒸馏。人工评测优于已有世界模型。**权重、代码和 benchmark 都已发布**，还附了轻量适配流程。

### Rethinking Verification in Agent Harnesses

[论文](https://huggingface.co/papers/2610.34577)

放在这一节，是因为它正好是 Genie 4 那个「外挂验证器」思路在纯文本侧的定量版本。

这篇把**验证**当作测试时扩展的一个独立维度来研究：何时介入、由谁检查、检查如何导向修改。框架覆盖 agent 生命周期的四层——初始指令、轮中提醒、完成门、独立复核。17 种设计 × 7 个前沿编码模型，在 Terminal-Bench 和 SWE-bench Verified 上对比，另建了 VisualBench 用于专家评估可视化与交互式产物。

按性价比排序，结论很清楚：

- 初始指令和执行期提醒：收益温和、依赖模型，但基本不增加输出 token。
- 完成门：收益更大，但**成本可能显著上升**。
- **独立 critic 复核：性价比最好**——Terminal-Bench 上平均准确率 +5.9 到 9.5 个百分点、SWE-bench 上 +3.9 到 6.6 个百分点，成本分别只有基线的 1.13–1.25 倍和 1.00–1.04 倍。VisualBench 上净偏好领先基线 13.2 到 23.8 分。
- 增加复核轮次或增加独立 critic，还能再提升最多 3.5 个点。

和 Genie 4 的架构选择指向同一个结论：**让一个独立的第三方来复核，比让生成者自己把关更划算。** 要给长程任务配验证，先做独立 critic，而不是先做自检。

## 关于本期的检索

本轮按轮换执行了三条常驻问题的主动检索（工程落地、反直觉的「其实不需要 X」、推理时学习的具身进展），中英各一次，**三条全部零命中**。

工程落地那条确实检出了两篇相关论文，但都在八九月推送过，按去重跳过；中文检索再次被「量化」一词拖进金融量化投资的语料里。反直觉那条四次检索全部落在消融实验的通用方法论解释和跨领域歧义上，没有任何一篇给出「去掉某个默认组件、性能不掉」的实证。推理时学习那条的中文检索只找到一篇企业新闻通稿，声称有在线学习框架，但没有迭代轮次、没有涨幅、没有饱和点，按判据不算命中。

连续多轮零命中不是正常状态，它说明问题问得太窄或检索词已经过时——描述性的检索短语（比如「消融实验表明某组件非必要」）钓不到东西，该换成这类论文实际会用的标题句式。这一条记在这里，是因为**一个只靠时间窗的信息源，结构上就抓不到「三个月前发布、今天才重要」的工作**，而问题锚定的那一层如果也失灵了，缺口是看不见的。

本期还有一个更值得记的教训：**相关度最高的那篇（TTME），是从机械预筛的「被砍掉」记录里捞回来的**，关键词分只有 3 分。这和此前漏掉评测标准化类论文是同一个病灶——基础设施、评测、负面结果这几类论文改变做法的程度最高，而摘要里的方法名词密度最低，在任何基于关键词的预筛里都会垫底。
