## 1. DELE-w0.5：视频生成是世界-动作模型的多余中间目标

[arXiv:2608.22067](https://arxiv.org/abs/2608.22067)（深度跃迁，深圳）

现在的世界-动作模型普遍建在视频生成骨干上，联合预测稠密的未来视觉轨迹和机器人动作。这篇的主张很直接：**对机器人操作而言，视频生成是一个不必要的中间目标。** 理由是世界模型的目的不是复现世界在每个中间时刻长什么样，而是预测动作执行完之后世界会到达的状态。中间帧只描述物理状态之间的视觉过渡，吃掉大量模型容量和算力，却不直接刻画这个动作意图产生的物理结果。

做法是从紧凑的**未来 latent state** 反推动作序列。这个 latent state 承载动作相关的物理结果，充当世界建模与动作生成之间的显式桥梁。训练时联合学习动作和动作完成后的未来世界表征；**推理时这一支被整个移除**，只靠语言指令和当前视觉出动作——因此推理成本回落到普通 VLA 的量级。视觉编码用 DINO-v3（头部视角加两个腕部视角），语言用 Qwen3，双流 Transformer。

四个长程任务、640 次真机试验：整任务成功率 62.5%，macro ordered-stage progress 81.3%，比最强基线分别高出 32.5 和 20.1 个百分点。中文报道另给了两段分布外演示：机器人拿着爆米花准备放进微波炉时实验人员把门关上，机器人保留手中目标物、重新开门再继续；另一次门只留一条窄缝，机器人没有回到训练里学过的把手流程，而是直接用手里的包装把门推开。报告称之为「目标条件下的行为重组」。

**它改变了什么。** 过去一年里，「给 VLA 挂世界模型分支代价太大」这个问题的主流解法是把视频那一支做小——稀疏视频 token、小型视频骨干、少步扩散。这条路默认了预测目标是对的、只是太贵。DELE 把问题重新定位成**预测目标本身选错了**：既然真正要的是动作后的物理结果，中间帧的监督信号从一开始就是冗余的，而不是「有用但太贵」。这两种诊断导向的工程决策完全不同——前者让你继续压缩视频分支，后者让你把整支做成只在训练期存在的辅助监督头、推理期直接砍掉。

## 2. Video Generators are Robot Policies：反方向的对照

[arXiv:2508.00795](https://arxiv.org/abs/2508.00795)（Columbia University + Toyota Research Institute）

这是一篇 2025 年 8 月的工作，不在当日窗口内，是带着「有没有实证支撑的『其实不需要 X』」这个固定问题主动检索捞回来的。它把视频生成当作机器人策略学习的**代理**，同时打两个约束：视觉与行为分布偏移下泛化差、性能被人类示范数据规模卡住。提出的 Video Policy 把视频生成与动作生成结合成一个可端到端训练的模块化框架。

两条结论最有分量：任务成功率与**生成视频的质量**紧密绑定；**无动作标注（action-free）的视频数据对泛化到新任务提供关键收益**。因此只用极少示范数据就能提取出可用策略，在仿真和真机上对未见的物体、背景、任务都有泛化，优于传统行为克隆。

放在上一条旁边读才有意思：DELE 说推理期不需要视频，Video Policy 说泛化恰恰来自视频，而且是无动作标注的视频。**两者并不矛盾，分歧在于视频是训练信号还是推理期计算。** 这让「要不要上视频世界模型」从一个是非题变成了按数据结构决定的选择题：如果瓶颈是带动作标注的示范太少、无标注视频很多，视频生成值得留在路径里；如果数据管够、瓶颈在控制频率，DELE 那条路占优。

## 3. Code World Model：让代码管演化，视频模型管观测

[arXiv:2608.25927](https://arxiv.org/abs/2608.25927)（西湖大学 AGI Lab + 南洋理工）· [GitHub](https://github.com/buaacyw/code-world-model)

同一个问题的第三个答案。核心论证讲得很清楚：视频记录的是世界演化之后的**可见结果**，不暴露产生这些结果的知识、规则和机制。游戏画面尤其典型——每一帧都由固定代码执行后渲染出来，可一旦变成训练视频，真正让世界运转的代码就被丢掉了，模型只能从稀疏的视觉后果里反推碰撞、攻击范围、阵营关系、任务状态。这个缺口在长时间尺度上更明显：当前视频模型的上下文通常短于一分钟，而角色关系和事件后果可能在世界时间里持续演化很久，且许多关键变化发生在镜头之外。

于是把「世界如何演化」和「世界如何被看见」拆成两个互补问题。Coding Agent 当世界大脑，推理事件及其后果，**生成可执行代码**来维护持久世界状态、执行规则一致的演化；代码是 Agent 的可执行延伸，不需要每一步都再调一次大模型。为了把不断变化的状态交给视频模型，引入一个 proxy 表示，编码逐帧的时空约束并编译成 proxy video，用来 condition 视频模型渲染高保真观测。配套做了从游戏录像与真实视频构造 proxy-observation 配对的数据流水线；在配对游戏数据上微调后，MiniMax-H3 能跟随 coding agent 搭建的简单交互世界的 proxy 时空规范。

目前验证停在游戏和简单交互世界，离操作任务还有距离，当方向性参考读比较合适。

## 4. Puffin-World：把重力场和纬度当成显式建模对象

[arXiv:2609.04196](https://arxiv.org/abs/2609.04196)

第四个答案。统一多模态架构，把物理理解、空间仿真、3D 世界生成与重建做进一条链路，不依赖外部离线模块。联合建模三种原生世界状态——**物理（重力场与纬度）、几何（深度）、外观（图像）**——外加一个统一的 Omni-Camera 表示支持多任务与灵活运动，并提出把物理动力学向未来帧传播的策略。通过把绝对相机属性锚定在真实世界上，得到物理一致、视觉稳定的世界生成；外观与几何耦合在同一个生成过程中，边合成未来视角边重建其几何。发布了 Puffin-16M：1500 万条 vision-language-camera 三元组加 100 万条轨迹，代码、模型、数据全开。

值得单独指出的是它对世界状态的拆法：把重力场和纬度当成**显式建模对象**，而不是指望它们从像素里涌现出来。把这四条放在一起，本期关于「世界状态该显式表示成什么」有四个不同的下注——DELE 押动作后的 latent 物理结果，Code World Model 押可执行代码，Puffin 押物理加几何加外观的三元组，Video Policy 押原始视频本身。这个问题目前显然没有收敛。

## 5. R2S-Eval：真机评测排名不稳，问题不在方差

[arXiv:2609.03276](https://arxiv.org/abs/2609.03276) · [项目页](https://r2s-eval.github.io)

随着通用模型特别是 VLA 被部署到实体机器人上，评测的重要性在上升，但常规真机评测有三个病：人力密集（反复硬件试验、手动复位场景、全程盯人）、**不稳定到「重复评测会给出不同的策略排名」**、以及主要依赖二值成功率因而信息量有限。作者的类比是，人评价机器人表现靠的是观察和比较完整行为，而不是只看二元成败。

方案分两段：real-to-sim 标定出一个对齐真实评测场景的仿真器，在其中高效生成 rollout 视频，减少重复硬件试验；再用 VLM 评价 rollout 的**执行质量**、产出成对偏好，聚合成策略排名。另外提出一套协议，用来检验这条流水线给出的策略结论是否真的成立。仿真与真机两侧实验称结论稳定、与人类偏好一致，大幅减少重复硬件操作，并能暴露二值成功标签捕捉不到的行为质量差异。

**它改变了什么。** 真机评测排名翻来覆去，常见的应对是多跑几轮把方差压下去。这篇给出的证据指向另一个诊断：**问题出在观测量太粗，不是样本量不够。** 二值成功率本身信息量就不足，补样本只会让一个粗糙的量收敛得更准，翻转依然会发生。真正该加的是执行质量的成对比较记录，以及一个「这个排名结论是否被验证」的判据，而不是更大的成功率表格。

## 6. Random Attention：KV cache 驱逐里，打分几乎不贡献

[arXiv:2609.03430](https://arxiv.org/abs/2609.03430)（Salesforce AI Research）· [代码](https://github.com/SalesforceAIResearch/Random-Attention)

现有 KV cache 压缩方法共享一个范式：给每个缓存 token 打一个「以后有多重要」的分，保留高分的。这篇的结论是**选择信号几乎不贡献任何东西**。Random Attention 保住 prompt，然后在每个注意力头内部**均匀随机驱逐**、完全不做打分，在四个模型六个推理任务上打平最强的既有驱逐器，而在 vLLM 部署下吞吐还高出 32–43%。

机制解释做得比结论更扎实，两条：其一，cache 里脆弱的部分是 **prompt**，各种选择器之间的差距，大多只是「它的打分信号碰巧有没有把 prompt 保住」；其二，推理轨迹自带两层冗余——文本层面上模型会边推理边复述自己还需要的东西，注意力头层面上每个头各存一份轨迹副本——所以只要 prompt 安全，随机抽样保留下来的副本就足够了，不需要任何评分来挑。

**它改变了什么。** 长上下文推理优化的常规思路是去比较和改进重要性估计函数，前提是收益来自打分质量。这篇把收益的来源换了个位置：决定成败的是**前缀有没有被保住**，打分只是碰巧做到了这件事的副产品。对任何要跑长程推理的系统，工程投入应该转向「把指令与观测前缀钉死、排除在驱逐之外」，剩下的历史随机丢即可——省下的不只是显存，还有打分本身的计算开销。

## 7. LAVLA：VLA 的隐空间逐层解耦，中间层最精细

[arXiv:2609.02634](https://arxiv.org/abs/2609.02634)

VLA 模型的内部表示驱动着它的行为，但这部分一直理解得很少。这篇对 GR00T N1.5 做逐层隐空间聚类分析，重点放在 action decoder 上。为刻画 action diffusion 过程中的隐空间，提出一种基于 cross-attention 的 embedding 加权方法，放大相关特征、压制信息量低的，加权聚类稳定优于基线；再为每个簇抽取人可读的概念，把隐表示连到语义描述上。

结论是隐空间的簇**逐层地把时空特征与运动学特征解耦开**，表示在中间层变得最精细，往输出层趋于稳定。这个梯度有实际用处：它给「从哪一层引出动作专家、在哪一层做跨本体投影」这类架构决策提供了一个可测量的判据，而不是只能靠反复调实验去试。需要注意这是单模型、单次分析，没有跨架构验证，别当通用结论用。

## 8. LatentPress：面向机器的记忆接口不该退化成人读文本

[arXiv:2609.01507](https://arxiv.org/abs/2609.01507) · [代码](https://github.com/xuyd16ai/context_softtoken_compress)

压缩后的上下文通常仍然写成人可读的文本，或者渲染成图片再解码，哪怕它的消费者就是语言模型本身。LatentPress 写成第三种表示：**连续的 memory token**，冻结的 decoder 通过 input-embedding 接口直接读，推理时不做任何文本重建。只训练一个 adapter（4.2M–26.2M 参数，约为 decoder 的 0.1%），压缩 4–16 倍。

数字里最说明问题的是对照组。LongMemEval 上，7.70 倍压缩得到 0.504 的准确率，**高于不压缩证据的 0.490**；而文本摘要只有 0.184，基于 OCR 的压缩从 0.426 掉到 0.312。写入耗时 43ms/会话，比文本摘要或 OCR 重建快约一个数量级；读取比原始上下文快 5–9 倍。两个迁移设定都验证过。LongBench-QA 上 4–8 倍压缩持平或优于直接读原文，16 倍开始掉队。

这对长程任务里的记忆问题是个侧面证据。让模型把状态写成一段自然语言摘要再喂回去，是目前最常见的做法；文本摘要那个 0.184 说明这条路径的信息损耗有多大。当然这是纯语言域的实验，没有涉及任何控制回路。

## 9. 单条训练样本就能撑起 on-policy 蒸馏的大部分收益

[arXiv:2609.04172](https://arxiv.org/abs/2609.04172)

On-policy 蒸馏把学生自己产生的 rollout 和教师的稠密 token 级监督结合起来。既有研究主要看算法行为，数据扮演什么角色一直不清楚。这篇把数据推到极小极限——只用一条 query 训练。

结果是单样本 OPD 能持续改进数百步，跨任务域和模型族恢复全量 OPD 的大部分收益。解释用的是**状态覆盖率**：单条 query 的 rollout 已经触达全量 OPD 所访问状态的 71.5%，其中大部分在前 100 步内完成；加入语义上不同的 query 会同时抬高覆盖率和验证精度，到 16 条达到 98.9%、追平全量训练。但**对齐速度与数据量几乎无关**——一条 query 和整个数据集的吸收速度差不多慢，即便状态集固定也要几百步才吸收得完。作者的总结是：OPD 是**数据过剩、算法饥饿**。这个结论在多教师设定下同样成立，每个域 16 条语义多样的 query 即可匹配全量。更狠的压力测试是，内容稀薄的模板和跨域的 WildChat query 也接近真实 query 的基线——**任务内容与它所诱导的状态覆盖是可以脱钩的**。

对做异构数据混训配比的启示是直接的：如果目标是覆盖状态而非覆盖任务，配比应该按语义多样性而非数据量来定，而且很快就会饱和。能否迁移到动作模型的蒸馏上需要另行验证——具身的状态空间由物理接触决定，未必能被十几条 query 覆盖住。

## 10. Scal3R：坏掉的只是全局位姿头，局部几何一直是好的

[arXiv:2609.04201](https://arxiv.org/abs/2609.04201) · [项目页](https://linjohnss.github.io/scal3r/)

在线 3D 重建在长视频上表现很差，原因被定位得很干净：相对**固定的首帧**锚点回归位姿，迫使模型外推到远超训练分布的地方，小的漂移不断累积放大成显著的几何塌陷。关键观察是——**逐帧深度在整个失败过程中保持稳定**。骨干网络的局部几何完好无损，坏掉的只有全局位姿头。

据此把在线重建重新表述为多参考的相对位姿查询：用约占 1% 参数量的轻量可学习 token，经非对称注意力注入一个**完全冻结**的骨干，向多个过去关键帧查询相对位姿；再配一套带回环检测的在线位姿图优化来抑制长程漂移。单卡 8 小时收敛，KITTI 上平均 ATE 相比在线基线降低 60% 以上，在 Virtual KITTI、Sintel、TUM-Dynamic、ScanNet、7-Scenes 上取得 SOTA。

方法之外，那个诊断本身更值得记住：**长时程感知栈崩坏时，先把局部几何和全局位姿分开测**，别一上来就认定表示学坏了去重训骨干。
