## 一、把接口从动作空间挪到图像空间

本期最值得读的是斯坦福李飞飞、吴佳俊团队的 [TrAct: Bridging Robot Control and Visual Prediction with Visual Tracks](https://arxiv.org/abs/2608.24101)（[中文解读](https://mp.weixin.qq.com/s?__biz=MzIwMTc4ODE0Mw==&mid=2247722484&idx=1&sn=e029fbc66cfcf32f1e544713bd322b92)）。

它切入的位置很窄，但选得准：**策略模型和世界模型之间传的是什么**。当前把世界模型挂进控制回路的做法，几乎都拿机器人动作当条件信号。问题在于动作是低维、与本体绑定的控制指令——Franka 和 UR5 做相似的操作可能需要完全不同的指令；而同一条指令最终产生什么视觉结果，又取决于场景几何、物体状态和接触动力学。于是世界模型被要求从稀疏的、本体相关的指令里推断稠密的视觉未来。论文引的已有研究把这件事说得更难听：动作条件视频模型**会忽略错误的动作**，转而依赖视觉先验生成一个看起来合理的画面。一个会忽略输入的条件信号，作为接口是失效的。

TrAct 换成**视觉轨迹**——任务相关点在图像空间里的二维运动。三个部件：VLAT 建在 π0.5 上，根据当前观测和语言指令**成对地**同时输出动作与视觉轨迹（轨迹不是由动作换算出来的，两者联合预测），跟踪夹爪上的 7 个关键点，腕部视角再加 5×5 个均匀采样的场景点作参照；TWM 以 Stable Video Diffusion 为骨干，通过 ControlNet 把轨迹编码成空间控制条件，生成未来视频；VLAC 按任务指令给候选视频逐一打分，执行最高分对应的动作（仿真每步采 20 组候选，真机 16 组）。

关键在于对照组设计得很干净：AWM 用完全相同的预训练与微调数据，只把条件信号从轨迹换回动作。LIBERO-INTEGRAL 上的阶梯因此可以逐级归因——

| 配置 | 平均成功率 |
|---|---|
| π0.5 基线 | 27% |
| VLAT（仅联合预测动作与轨迹，无世界模型） | 44% |
| VLAT + 动作条件世界模型 AWM | 49% |
| TrAct（VLAT + 轨迹条件世界模型 TWM） | 55% |

三个独立随机种子重新评估，TrAct 54.7% 对 VLAT+AWM 49.0%，95% 置信区间不重叠。视频预测质量的差距更大：仿真外部视角 PSNR 从 15.12 升到 24.51，LPIPS 从 0.438 降到 0.106，FVD 从 129 降到 38。动作条件世界模型的典型毛病——夹爪姿态错误、物体凭空消失、跨视角位置不一致——换成轨迹后明显收敛。真机 Franka 面对未见任务和背景变化，成功率从 49% 到 76%。值得注意的是标准 LIBERO 已经饱和（π0.5 96.8%、TrAct 98.3%），所以团队专门构造了带分布偏移与跨本体设置的版本，泛化那部分才是这篇的战场。

**这篇改变的是问题的位置。** 跨本体统一这件事，目前的主流讨论集中在动作空间：per-embodiment projector 还是动作 tokenizer，关节角还是末端位姿，争的都是同一层。TrAct 给的证据说明这一层未必是瓶颈所在——图像空间的点轨迹是本体无关的，对未来预测的约束又比动作明确得多。往下有两条具体推论。其一，只要在候选筛选回路里挂了世界模型，就不该用动作去条件化它：同数据同流程，仅换条件信号就是 49% 到 55% 且区间不重叠。其二，视觉轨迹构成了第三条对齐轴，不在「关节还是末端」的二选一里；「统一动作表示」这个问题，可能有一部分根本不应该在动作空间里解。

还有一个容易被大结果盖住的细节值得单独拎出来：VLAT 那一档 27%→44%，**没有任何世界模型、没有任何候选筛选**，纯粹是让策略多输出一路轨迹监督。这意味着视觉轨迹首先是个便宜的辅助监督信号，收益可以脱离整套预演-筛选流程单独验证。对想借鉴这条思路又不愿意背上视频生成开销的人，这是成本最低的切入点。

## 二、一个准确率里装了两种能力

[GUI-Primitives: Diagnosing Spatial Reasoning Failures in Vision-Language GUI Grounding](https://arxiv.org/abs/2608.21832)（[HF](https://huggingface.co/papers/2608.21832)）做的是一件方法论上很规矩的事：把一个被合并计算的指标拆开。

基准由 994 条**对比式指令对**组成，覆盖七种空间关系（左右、上下、包含、对齐、邻近、列表序数、遮挡）。构造方式是关键：每一对里截图和锚点固定不动，只改关系表述，正确目标就在两个指定候选之间切换。这样一来，同一对内部的分数差异只能归因于关系理解，而不是图像难度或元素显著性。196 条子集经五名标注者验证，良构性 κ=0.94，目标选择 κ=0.79。

十九个视觉语言模型跑下来，严格的 point-in-box 准确率**最高只有 32%**。真正有价值的是接下来这步分解：因为模型输出的是无约束坐标，作者按预测落在哪个候选区域来分类，发现 **60% 到 92% 的预测两个候选区域都没落进去**。而一旦把统计条件在「落进了某个候选区域」上，目标选择准确率对水平位置、垂直位置、邻近、列表序数达到 0.82–0.90——**但包含与遮挡不显著区别于 0.50**，也就是瞎猜。把两个候选显式标出来，选择准确率提升 35 到 57 个百分点（作者明确说这是 oracle 诊断，不是可部署的方法）。与 ScreenSpot-Pro 的相关性 Spearman ρ=+0.74，在这个样本量下只算探索性关联。

结论是：**总分里绝大部分是候选定位失败，不是关系理解失败**，而这两件事被一个数字合并了。落到评测设计上，改动很具体——报告 pointing / grounding 能力时不该只给一个准确率，要分开报「定位成功率」和「条件在定位成功之上的关系选择准确率」。否则一个只是定位变准的模型，在榜单上看起来会像是空间理解变强了，这正是「指标涨了但实际没变强」的标准形态。另一个可直接行动的结论：包含与遮挡卡在随机水平、其余关系已经到 0.85 左右，说明补训练数据要定向补这两类，均匀加量是浪费。

这篇的载体是 GUI 截图而非机器人场景。但它诊断的能力——把关系语言绑定到图像里正确的那个元素——和具身侧的 pointing、referring 是同一个，评测方法论可以直接搬过去。

## 三、蒸馏与量化不该排成流水线

[GRACE: Gated Relational Alignment via Confidence-based Distillation](https://arxiv.org/abs/2601.22709)（ICML 2026，作者陈彦龙，ETH Zurich；[代码与量化权重](https://github.com/ForeverBlue816/GRACE)，[中文解读](https://mp.weixin.qq.com/s?__biz=MzIwMTc4ODE0Mw==&mid=2247722484&idx=2&sn=4e01fedcc314721790fbd3e36eccd024)）针对的是把多模态模型塞进手机、车机、边缘设备的标准流程：先知识蒸馏出小模型，再对小模型做训练后量化。这条路在 8-bit 上还算稳，压到 4-bit 明显掉点。

论文的归因有两条，第二条是常识、第一条不是：

**蒸馏阶段不知道自己后面要被量化。** 学生在全精度下学到的表示可能分布尖锐、动态范围大、离群值多，恰恰是最不适合低比特承载的那一类。于是出现一个反直觉的后果——**蒸馏优化得越好，量化时反而摔得越重**。第二条是常规的：到了量化阶段教师已经用不上了，PTQ 只剩一小批校准数据和一个定型的学生，量化误差引入的表示偏移再也纠正不回来。两个阶段各自的最优解拼在一起，不是整体的最优解。

GRACE 把量化感知训练和蒸馏放进同一个目标下联合优化，三个模块各回应一个问题。GDKD 处理「教师的哪些输出值得学」：用教师输出分布的归一化熵构造门控权重，教师越确定蒸馏权重越高；作者用 Fano 不等式论证条件熵与可达错误率下界的联系，说明这不是拍脑袋的启发式，损失本身沿用解耦知识蒸馏拆成目标类与非目标类分别加权。RCKA 处理「除了输出分布还有什么值得对齐」：在 LLM 倒数第二层取视觉 token 的表示算 Gram 矩阵，用中心核对齐度量师生两侧**关系结构**的一致性。理由是量化扰动的是每个 token 的激活数值，而同一张图里 token 之间的相对关系相对稳定、也更接近模型真正利用的语义；CKA 对正交变换和整体缩放不敏感，正好适配「学生维度低于教师且数值被量化扰动」的场景。取倒数第二层是消融出来的选择——更浅的层语义不足，最后一层已经过度贴合词表输出。第三块是自适应信息瓶颈控制器，动态配平上述两项与任务损失，避免固定权重在训练不同阶段失衡。

Qwen2-VL 7B→2B 上，4-bit 的 GRACE 学生在八项基准平均 68.0，超过 BF16 学生基线 4.0 分，超过此前最强的 4-bit 方法 SPEED-Q 5.7 分，与 7B 全精度教师的差距压到 3.7 分以内。

**可迁移的判断有两条。** 一是把「压小」和「压窄」当成两个可以分开做、顺序无关的工程步骤，这个默认假设是错的；顺序本身是变量，而且中间那个全精度学生越好未必最终越好。二是蒸馏对齐的对象值得从「数值」换成「token 之间的关系结构」——这一条的适用范围可能比量化更宽，在其他会扰动激活数值的场景下同样值得一试。

需要划清的边界是：这套结论建立在纯视觉语言基准上，**没有任何策略成功率的证据**。量化对真机控制策略成功率的影响仍然是一片空白，不能把八项基准平均 68.0 这类数字外推成「策略不掉点」。

## 四、按语义密度配数据，而不是按数据来源

腾讯微信视觉团队开源了 [WeMM-Embedding](https://mp.weixin.qq.com/s?__biz=MzIwMTE1NjQxMQ==&mid=2247664612&idx=1&sn=6b36f0274ec234d1116ad9740c55f33e)，基于 Qwen3.5 的通用多模态向量表征模型，2B / 4B / 9B 三档，代码与全量权重开源，支持 Matryoshka 表征学习。MMEB-v2 上 2B 得 77.9 分越级超过此前领先的 8B 开源基线，9B 以 80.6 登顶总榜；并在视频号、公众号、朋友圈、搜一搜完成 14 次线上 A/B 与大规模部署。

榜单不是这条值得记的理由，数据侧的两个做法才是。

**统一 Pair 协议。** 分类、图文检索、视频定位、问答推理被统一抽象成「源实例—目标候选」之间的相关性度量，样本元组里带可选的任务指示指令、显式挖掘的难负例集合，以及可选的**分级相关性得分**；源端与候选端都支持纯文本、图像、视频或图文任意交织。把形态各异的任务压进一个模式，代价是表达力，收益是数据可以互相通约。

**Semantic-ID 逆密度重采样。** 针对网络数据长尾不均，团队用中间检查点的表征做三层残差 K-Means 聚类，生成语义离散标识，然后对高频语义簇降采样以提升长尾覆盖，构成规模约为全量十分之一的 Stage-2 精选集；配套还有 MLLM 清洗改写和模态自适应难负例挖掘。

值得留意的是最后这个思路对**异构数据集混训**的潜在意义。目前多来源数据的配比普遍还是按数据集来源手工调，这本质上是拿「数据从哪来」当成「数据讲了什么」的代理——同一个来源内部的语义分布可能极不均匀，不同来源之间又可能大量重叠。在表征空间里聚类、按语义簇密度反向配比，给的是另一条路。这条能否搬到动作模态上还完全是开放问题（缺一个足够好的动作表征当聚类底座），但它至少把「按来源配比」从默认选项变成了一个需要辩护的选择。
