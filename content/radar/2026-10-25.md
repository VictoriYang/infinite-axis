## 1. GSR / ParaVLA：指令换个说法就崩，坏的不是语言理解

[arXiv](https://arxiv.org/abs/2608.02497) · [代码](https://github.com/AutoLab-SAI-SJTU/GSR-ParaVLA) · 上海交大 AutoLab + 无界动力

先给现象。作者基于 LIBERO-Goal 构了 LIBERO-Para：场景、物体、初始状态、成功判据全不变，只改写指令里的动作表达和物体描述，共 4,092 个 episode（动作改写 870、物体改写 259、组合改写 2,963）。SmolVLA 从 72.0% 掉到 **4.47%**，VLA-Adapter 从 98.2% 掉到 **46.82%**，大规模异构数据训出来的 π0.5 也只剩 73.60%。

关键不在现象而在归因。两组探针给出的结论是：**任务身份其实已经被正确编码在模型内部，坏的是语言和动态视觉观测的联合编码引入了系统性特征偏移，而下游 action expert 对这种偏移完全没有不变性。** 证据一，只把辅助分支的图像换成 dummy image（主视觉分支仍吃真实观测），让任务语言表示不再随动态图像一起变，VLA-Adapter 就从 46.82% 升到 61.58%。证据二，用 8 个任务估出 32 个能区分原始指令与改写指令的特征方向，从另外 2 个未见任务的改写特征里减掉——动作差异从 0.4361 降到 0.2282，20 个闭环 episode 的成功率从 55% 升到 90%；减掉同样数量、同样范数的随机方向则基本不动。

解法 GSR 只有三步：冻结的 T5 单独编码指令（不吃图像、不吃状态），投影后重新注入各模型自己的多模态融合位置，然后把 action expert 重新初始化、从头训。**只用原始指令训练、不加任何改写数据**：VLA-Adapter 46.82 → 70.94，SmolVLA 4.47 → 49.12，π0.5 73.60 → 75.59。

两个对照实验才是真正值钱的部分。一是**只在旁边挂一个 T5 几乎没用**：VLA-Adapter 的 Native+T5 只从 46.82 到 47.31，SmolVLA 只到 13.49——起作用的是信息流被重排，不是"多了个语言编码器"。二是路径控制权：两条路径都喂对指令时 47.31%，给原生 Qwen 路径喂错任务掉到 5.11%，给 T5 路径喂错仍有 44.0%——原生路径牢牢握着动作控制权，这决定了注入点必须按架构来定。论文另外放了个彻底解耦的 0.33B 模型 ParaVLA（冻结 T5 + DINOv2，在 action expert 里融合），LIBERO-Goal 原始 92% / 改写 91%，只差一个点；代价是视觉侧放大时没有 VLM 那种 scaling 行为。

它改变的默认做法很直接：指令泛化掉点时，大家的第一反应是去采改写数据或堆更大规模预训练。"旁挂一个稳定语言编码器"（+0.49pp）和"重排信息流并重训 action expert"（+24.12pp）之间差了五十倍，说明该先做的是定位哪条路径握着控制权，而不是先去采数据。

## 2. 视角换了就掉点，是表示漂移而不是能力缺失

[arXiv](https://arxiv.org/abs/2512.02902) · 中山大学等

把 VLA 拆成两块：空间建模（ViT 视觉编码器，负责从图像构出物体间的位置、朝向、接触、遮挡关系）和物理建模（VLM + action expert，负责任务语义到动作动力学的映射）。论证的是换相机视角后掉点，主因在空间建模的输出失配，不在物理建模的推理能力。直接证据是 embedding drift：零样本下新视角的视觉 token 和训练视角的 token 在嵌入空间里形成**完全分离的两簇**，轻量适配之后两簇对齐，性能随之恢复。

于是方法可以做到荒谬地轻。FTM 就是对视觉 token 做一次全局仿射 `F̂=(1+γ)⊙F+β`，γ、β ∈ R^2048，一共 **4K 个参数**，把 LIBERO 的视角准确率从 48.5% 抬到 87.1%。FLA 再给 SigLIP 的 ViT 线性层加低秩更新，**4.7M 参数拿到 90.8%**，而 π0.5 的 LoRA 微调是 467M 参数拿 90.3%——99 倍参数缩减且略有反超。适配是 one-shot，每个新视觉域只要 1 条人类演示，单卡 A100 上 1500 步收敛。

作者另建了 Libero-V（相机视角、光照、背景纹理、传感器噪声四种受控扰动）：FLA 四种扰动平均 94.8%，和 π0.5 LoRA 的 94.6% 持平；FTM 90.5%，远超 prompt 学习的 75.1%。秩从 16 到 32 只有 90.8 → 91.2，边际收益很小。真机在 Franka Emika Panda 上做了 5 个任务（拾积木、堆积木、关微波炉门、按按钮、拉抽屉），单次适配后在新相机视角下全部完成。

它顶掉的是两条都很贵的既有路线：数据中心范式（扩视角数据）和表示中心范式（几何一致性 / 3D 感知架构）。如果视角脆弱性的本质是视觉 token 的分布漂移，那么合理的第一步是先量一下新视角的 token 和训练视角是不是分成两簇，是就先做 token 级仿射校准，只有校准不动的那部分才值得去采数据。顺带一个推论：把"换相机就掉点"当成模型缺乏空间理解能力的证据，这个归因是错的。

## 3. LIBERO-Plus 回读："模型忽略语言"是过度结论

[arXiv](https://arxiv.org/abs/2510.13626) · 复旦

这篇在七个维度上做受控扰动：物体布局、相机视角、机器人初始状态、语言指令、光照、背景纹理、传感器噪声。核心数字是模型对相机视角和机器人初始状态极度敏感，温和扰动下成功率从 95% 掉到 30% 以下。而被引用得最多的那句是：**模型对语言变化基本不敏感，进一步实验显示模型倾向于完全忽略语言指令。**

把三篇放一起才看得清楚。LIBERO-Plus 的"忽略语言"是从外部行为反推的，GSR 的探针直接查了表示、发现任务身份是保留的。两者并不矛盾，但"忽略语言"这个说法走得太远——真实情况是**在 LIBERO 的大部分任务里视觉场景已经足够消歧，语言不被需要**；一旦换到 LIBERO-Goal 那种场景物体全固定、只有目标不同的设置，语言突然变成唯一的任务选择器，改写一下就从 98.2% 掉到 46.82%。同理，它测出的"相机视角最脆弱"是真的，但第 2 篇证明那不是能力缺失而是表示失配。

这件事有两个可操作的后果。其一，**测指令跟随能力必须用场景固定、仅目标变化的任务族**（LIBERO-Goal / LIBERO-Para），在 LIBERO-Spatial / Object 上测语言等于没测。其二，引用任何"模型不用某个模态"的结论之前，先问它是行为级证据还是表示级证据——"行为上对某个模态的扰动不敏感"和"表示里没有这个模态的信息"是两回事。

## 4. TrajSkill：用稀疏光流当跨本体的第三个对齐轴

[arXiv](https://arxiv.org/abs/2510.07773)

从人类示范视频学操作技能，难点是人体和机械臂之间的本体鸿沟；已有做法要么要配对数据集要么要手工奖励。这篇把人类动作表示成**稀疏光流轨迹**，当作与本体无关的运动线索——去掉形态差异、保留必要动力学；以这些轨迹加视觉和文本为条件，联合生成时序一致的机器人操作视频，再翻译成可执行动作。MetaWorld 仿真上 FVD 降 39.6%、KVD 降 36.6%，跨本体成功率最高提升 16.7%，真机在厨房操作任务上验证。

值得记的是它提出了一个不同的对齐轴：稀疏光流既不是关节空间也不是末端位姿，**它放弃了"人和机器人的动作要一一对应"这个前提，改成只对齐可观测的运动模式**，因此绕开了 retarget 问题。推论是异构数据集混训时不必把所有数据压进同一个动作空间——人类视频这类无法 retarget 的数据，可以只提供运动线索而不提供动作监督。局限也清楚：主要指标是仿真 FVD/KVD 加一个区间上界，没给出光流表示在精细接触任务上的失效边界。

## 5. LIBERO-X：从单维度扰动走向累积扰动

[arXiv](https://arxiv.org/abs/2602.06556)

论点是现有 VLA benchmark 因为评测协议不足、没有充分刻画真实世界的分布偏移，给出的评估"有限甚至误导"。做了两件事：一是分层评测协议，难度逐级递进，瞄准空间泛化、物体识别、任务指令理解三种能力，目的是看出性能随环境与任务复杂度上升怎么衰减，而不是只给一个总成功率；二是配了一份人工遥操作采集的高多样性训练集，每个场景支持多个细粒度操作目标，用来缩小训练与评测之间的分布差。实验显示代表性 VLA 在累积扰动下显著掉点。

和 LIBERO-Plus 的分工值得注意：后者是单维度受控扰动（哪个维度最脆），这篇是累积扰动加分层难度（脆弱怎么叠加）。真机上从来不是只换相机不换光照，所以后一种形状更接近现场。

## 6. 把"可重复性"从流程纪律变成算法性质

[arXiv](https://arxiv.org/abs/2505.08216)

这篇没有任何方法名词，纯讲评测算法本身的性质。它把一个标准化测试算法该满足的性质列成三条：准确性（接近通常未知的真值）、效率（在可接受的成本和设备约束内可行）、可重复性（不同人、不同时间、不同地点执行相似的测试算法，在同一台机器人上应该得到一致结论）。然后指出第三条正在变难，因为被测系统越来越复杂、智能、多样，**而且最关键的是随机**。

针对标准化评测里用得最多的一类算法——statistical query，即从采样数据估计某个有界函数在分布上的期望值——提出一个轻量、带参数、自适应的改造，可以套在任何 SQ 流程上（蒙特卡洛采样、重要性采样、自适应重要性采样都行），使其可证明可重复，且准确性和效率都有保证上界。三个验证场景：机械臂的既有标准化测试、自动驾驶运行风险评估、人形机器人运动任务里的指令跟踪性能评估。

它的价值在框法本身：比较两个 checkpoint 时跑的其实就是一个 SQ 流程（固定若干初始状态、估成功率的期望），而"可重复性"原来被当成靠流程纪律维持的东西，这里把它变成可以被算法保证的性质。具体改造能不能直接套到桌面操作的 rollout 脚本上，摘要不足以判断，三个验证场景也都不是桌面操作。

## 7. 用 LeRobot 讲数据质量：平滑的数据不等于好数据

[原文](https://juejin.cn/post/7689656350306009134)

围绕 LeRobot × LanceDB 集成写的工程判断。核心机制是 `LeRobotDataset` 可以直接读 Lance 表，从对象存储按批取数、全局打乱，并把视觉向量、动作粗糙度、成功标记放进**同一张版本化表**，让训练器读的版本和分析人员搜索的版本一致。DROID 实验规模 2763 万帧 / 95,658 episode / 369GB 视频；相同采样顺序下远程 LanceDB 稳定吞吐 495 样本/秒、本地 NVMe 361（作者自己标注这是特定缓存与布局的结果）。

真正有用的是三个误区。一、**全局随机打乱不防泄漏**——同一住宅、同一操作者、同一段连续录像被拆到训练和验证两边，验证集照样泄漏；要先选不跨集合的分组键（房屋 / 站点 / 用户 / 采集批次）再切，而不是先随机后补标签。二、**越平滑的数据不等于越好**：该文转述官方实践在 DROID 上的发现，成功 episode 反而更抖，单一平滑度指标的 AUROC 只有 0.402，低于随机。三、固定随机种子不等于可复现——数据版本、筛选查询、视频解码器变了结果照样漂。文中还给了一份可落地的数据契约（每 episode 固定采集地点与设备、操作者编号、任务指令、起止时间、成功定义、原始文件哈希；派生特征必须记计算代码版本且不覆盖原值），以及两层质检的分工：自动层只能保证"能读"（缺帧、时间戳倒退、动作越界、相机数、字段类型），**一个格式完美但把杯子放错桌面的 episode 仍然会混进训练集**，所以人工层必须抽看模型最难的、指标最异常的和随机采样的轨迹。

> 核对缺口：AUROC 0.402 这个数字是该文转述官方帖子的，一手帖子抓取返回空，**这一条按二手对待**。文中其余内容是作者自己的工程论证。

第二个误区的后果最实际：把动作抖动 / 平滑度做成一个自动质量分去筛 episode，是数据平台上最省力的起点，但如果平滑度和成功率在 DROID 上近乎反相关，这个分数会**系统性地筛掉成功样本**。更稳的做法是抖动只进自动层当"能不能读"的异常检测（用真实设备的正常轨迹先建分布，而不是拍一个阈值），质量标签一律不由平滑度派生。训练 / 验证切分改成先定分组键再切，这一条不依赖那个二手数字。

## 8. UI2App：只给静态截图，能不能把隐含的交互推断出来

[arXiv](https://arxiv.org/abs/2607.06306v2) · [项目页](https://chenmancm169.github.io/UI2App-ProjectPage/) · [代码](https://github.com/chenmancm169/UI2App) · 港科广

和具身没有直接关系，收它是因为评测设计的形状可以搬。任务叫 Interaction Inference：只给静态 UI 截图，不给功能说明、不给点击轨迹、不给交互演示，模型要自行推断截图里隐含的应用行为并实现成一个能跑的多页 React 应用。规模是 600 张截图组成 95 组状态一致的多页应用，每个任务 3-14 张截图，共 665 个"应用-交互类别"评测项。

可搬的部分有两处。一是**三个指标把"像"和"对"拆开**：EXEC（能不能真的构建运行）、VFS（和截图有多像）、IIS（截图暗含的交互是否被覆盖、是否真产生预期结果、相关状态能否在组件和页面间正确保持）。论文开头那张图的意思就是：同一组截图、同一操作序列下，视觉还原更高并不保证购物车的状态逻辑被正确实现。二是**按状态作用范围分难度**：S1 局部 UI 状态（按钮、下拉框、标签页）、S2 多组件共享的数据状态（搜索、排序、CRUD）、S3 跨路由持续存在的状态（购物车）。

"视觉相似度高但状态逻辑错"是"指标涨了但实际没变强"的一个干净样本；而"按状态作用范围分级"这个轴搬到具身评测上就是**按记忆跨度分级**——单步接触、跨子任务共享的物体状态、跨 episode 持续的任务进度，这比按任务名罗列 benchmark 更能定位是哪一段断了。

## 本期没收进来但值得一提

- **Apple 的 Instruction-Following Pruning**（见于公众号转述）：一个小预测器先读指令再挑 FFN 要激活的行列，权重完整放闪存、**按请求而不是按 token** 挑专家搬进内存，每次上场 10-40 亿参数。这个粒度对真机 VLA 很合适（一个 episode 内任务指令是固定的），但手上只有转述、没有回读一手报告，所以不单列。
- **Data Analogies Enable Efficient Cross-Embodiment Transfer**：跨本体方向本轮最强的检索命中（成对演示比堆非成对数据有效，真机 +22.5%；末端形态变化下无结构多样性几乎无增益），此前已推荐过。
