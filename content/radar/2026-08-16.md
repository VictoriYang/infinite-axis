## 一、世界模型的判据在变

### 1. FACT：让失败教「后果」，而不是教「行为」

[arXiv 2608.10232](https://arxiv.org/abs/2608.10232) · [项目页](https://fact-wam.github.io/) · [代码](https://github.com/Bariona/FACT) · UC San Diego

问题诊断得很准。现在的 world-action model 有两种主流接线：生成未来视频再用逆动力学反解出动作，或者把预测出的视频当作目标条件去驱动动作。两种都**几乎只在成功演示上训练**，于是世界模型「没有任何理由去预测坏动作会导致什么」。失败 rollout 无处安放，只能丢掉——而这恰恰是最容易采到、也最能说明问题的那部分数据。

FACT 把因果顺序倒过来：**先出动作，再基于已经执行的那个动作去预测未来视频和任务进度**。一个 causal diffusion transformer，value 头和未来视频都条件于「干净的」动作，而带噪的动作 slot 看不到它——这样未来预测能反过来锐化动作生成，又不至于把答案泄漏给正在去噪的动作。

有了这个 action-conditioned 接口，失败数据就有了正当用法：**屏蔽掉动作模仿的 loss（不要学这个动作），但仍然用它监督「实际观测到的那个失败的未来」和一个被压低的进度值**。教的是后果，不是行为。副产品是 value 头因为见过失败结果而变得对动作敏感，推理时可以拿来给若干候选动作排序。

数字站得住：RoboTwin 仿真 50 个任务平均成功率，加入失败协同训练后到 **87.5%**，与最强基线持平但**部署速度快约 3 倍**；真机双臂任务（插螺丝刀、拉工具包拉链、装箱合盖、开瓶盖）在见过的任务上从 **82% 提到 89%**，加候选打分到 **92%**，而且**没有用任何机器人预训练**；失败数据越掺越好，没有出现早期饱和。

最有说服力的是最后一条消融：在失败 rollout 上，未来预测的 PSNR **提高了 6.4 dB**，而成功轨迹的预测质量不变。也就是说，「只用成功数据训出来的世界模型，会在你做错动作时依然幻觉出一个成功的抓取」——这个偏差被定量地测了出来，也被修掉了。

改变了什么：它把「失败数据该怎么用」从一个数据清洗问题变成了一个接口设计问题。此前失败轨迹的用法基本只有一种——标成恢复演示再去模仿；FACT 给出第二种，直接作为世界模型的监督目标，不需要额外的奖励模型，也不需要人工标注。

### 2. 一位智驾量产负责人对世界模型的三分法

[对话郎咸朋（量子位，1.9 万字实录）](https://mp.weixin.qq.com/s?__biz=MzIzNjc1NzUzMw==&mid=2247912624&idx=2&sn=91c2c8e5fccbed8520e2a22261928d41)

理想智驾从 0 做到 150 万辆量产的核心负责人之一，现在出来做机器人。访谈里有几处是一手的技术表态，不是转述别人的结论，值得单独摘出来。

**他把「世界模型」这个被用滥的词拆成了三类**：渲染器（出像素，视频生成）、仿真器（对状态和动力学做仿真）、以及输出动作的。他的立场是三者缺一不可——**一个好的世界模型要能渲染、能生成动作、还能评价自己的生成**。这个三分法比这个词本身有用得多，可以直接拿去给论文归类；顺着这个分法，上一条的 FACT 恰好是三样都做的那一类。

**架构上他给了一个明确的不同意见。** 现在用 MoT（Mixture-of-Transformers）的人不少，但通常**按模态**分专家——文本一个、视频一个、动作一个。他们是**按因果角色**分：目标 → 动作 → 结果，并且设计了一个注意力**单向流动**的机制：做动作的时候只允许看到目标，不许偷看结果，否则就是作弊，也违背因果的第一性。

这一点值得停一下：它和 FACT 里「带噪的动作 slot 不能看到干净动作」是同一类顾虑——**在同一个网络里同时做预测和决策，就必须防止决策端把答案抄过来**。两个团队从完全不同的出发点独立撞上了这个坑，说明它大概是这条路线上一个结构性的约束，而不是某个实现的偶然。

**关于数据，他给了一个公式和一条反直觉的判断。** 公式是「数据效率 = 获取效率 × 使用效率」。判断是：自动驾驶的成功建立在数据能近乎零成本获取（影子模式），而具身没有这个前提，你不可能先把机器人放到用户家里让人手动操作两年——所以**该在使用效率上下功夫，而不是继续卷获取规模**。他们的做法叫「数据编译」：先用模型把场景里物体的物理量（重力、重量、受力、摩擦）**显式算出来**（他特别强调不是靠加装力/触觉传感器去采，因为大量现成数据里根本没有这些通道），再沉淀物理机制，编译进训练样本，最后用回传机制挖掘表现差的数据重新编译。结论是 UMI 数据、第一人称数据、合成数据、互联网数据**都不能直接拿来用**。

**最后是一个可以直接抄的评测设计。** 他说要检验机器人到底是理解还是死记硬背，测试集里必须包含训练集**没出现过的物理量**——训练全程只给空杯子，评测时往杯里装不同深度的水，看它端起来会不会洒。这比换物体、换背景那类 OOD 测试更贴近「理解」二字，而且实现成本极低。

他的非技术判断可以当作行业温度计：现在的具身像自动驾驶的 2015 到 2016 年，路线未定、demo 满天飞、操作能力上**没有一家真正出货**；洗牌的触发点只有一条，量产交付能否自我造血；以及别只盯着「操作智能」，运控、交互、移动同样是具身的组成部分，只是拿来做 demo 不够好看。

### 3. CoRL 2026 的一份征稿，顺手写出了世界模型的验收清单

[Workshop 主页](https://arlo0o.github.io/Grounded-Driving-World-Models_Workshop/) · [中文征稿说明](https://mp.weixin.qq.com/s?__biz=MzIwMTE1NjQxMQ==&mid=2247664030&idx=2&sn=3cbcc6ea1ef4efa61fcfb860f37f6e4c)

CoRL 2026 的半天 workshop，11 月 12 日在 Austin，投稿截止 **10 月 12 日**（UTC 11:59），走 OpenReview，明确欢迎新问题、新资源和**负面结果**。已确认的讲者里有 Hao Zhao（清华）和 Hongyang Li。

收录它不是因为征稿本身是成果，而是因为它把上面那个判据的转向**写成了一份可以直接照着用的清单**。CFP 的原话是「从 world model can generate 走向 world model can support decision making」，落成五个问题：有没有稳定、可解释的 4D 几何 / 语义 / 动态结构？能否生成与真实多相机、LiDAR、传感器装配一致的多模态观测？能否服务规划、控制、策略学习和闭环评测，而不只是离线展示？能否可控地生成长尾、对抗、反事实和 safety-critical 场景？**评估该只看 FID / FVD，还是该看 planning utility、碰撞、可行驶合规与失败迁移？**

虽然写的是自动驾驶，这五问把名词换掉就能拿去审任何一篇具身世界模型的论文。最后一条尤其是老问题的新说法：生成质量指标涨了，下游决策并没有变好。

## 二、长程自主缺的不是能力，是两块工程拼图

### 4. Chelsea Finn：记忆的 token 预算，和用元数据驯服脏数据

[完整逐字稿](https://www.ycrootaccess.com/p/chelsea-finn-on-the-next-decade-in) · [视频](https://www.youtube.com/watch?v=cRZNwgvcWUg) · YC Startup School 2026

Physical Intelligence 联合创始人的演讲，难得的是有完整逐字稿和消融数字，不是务虚。里面有四处内容值得记。

**为什么「可靠性」是个新问题，而不是老问题的加强版。** 她给了一个很干净的框架：迄今为止所有成功落地的机器学习——推荐、广告排序、ChatGPT、编程助手——都是**人拿着模型的输出去做最后那个决定**，所以模型犯错是可容忍的，人能识别、能兜住。物理 AI 不一样，它直接对物理世界下决定，只有在完全自主时才真正有价值，因此对错误率的要求比此前部署过的任何 ML 系统都高一个量级。这解释了为什么机器人领域「demo 很惊艳、落地很难」不是执行力问题，而是判据不同。

**真机强化学习的两处效率修正。** 语言侧的 PPO / GRPO 靠几百万到几千万次尝试起效，折算到一个一分钟的机器人任务大约是 **700 个机器人日**——不可行。他们改了两个地方。一是**不让死胡同轨迹跑完**：机器人一次抓起了两个紧贴的纸箱，再往下折是纯粹浪费真机时间，此时人遥操介入示范如何从这个状态恢复，或者干脆早停。二是**不再对同一个初始状态反复 rollout 去估值**，而是把这个成本摊到不同任务上，用大量机器人视频训练一个通用的 value function，预测「到成功还剩多久」——同一个 value 既能判断叠衣服时把衣服叠反了是负进展，也能判断从冰箱取物的进展，跨场景可用。

结果：仅强化学习这一段带来约 **2 倍吞吐**，espresso 任务成功率 **超过 90%**，并且**连续运行了 13 小时**；同一套算法搬到一家巧克力工厂的真实纸箱产线（折箱、贴标、堆叠）和没去过的家庭里叠衣服，都成立。

**记忆：她把代价算给你看了。** 当前多数机器人基座模型**没有上下文**，只吃当前观测。朴素地把历史视频塞进去是什么量级？10 秒视频、50Hz 控制频率、4 路相机、每帧 256 token，约 **50 万 token**；降采样到 1fps 仍是 1 万 token——实时跑不动，而且这还只买到 10 秒的记忆。他们的方案是**多时间尺度记忆**：约 10 秒的短时视频记忆（用更高效的方式计算，不是硬塞），加上分钟到小时级的记忆**压缩成文本摘要**再喂回模型。靠这个跑通了 10 到 15 分钟的**非重复**长程任务——擦台面、用纸巾擦干、扔掉纸巾、把芥末收进冰箱、把碗碟放进柜子、洗掉水池里的脏碗。

这一步的意义在于，长时记忆退化成文本是个**不需要改动骨干网络**的方案。当下把记忆做进控制回路的尝试大多集中在循环状态或快权重上，而「近处用视觉、远处用语言」这条路提供了一个完全不同的容器。

**π0.7：让低质量数据从负资产变成正资产的开关。** 他们把手上所有数据都混进训练——包括**低质量演示**、策略自己跑出来的 rollout、人类操作视频、网络数据。关键的解锁点不是模型更大，而是**把上下文尽可能作为 prompt 显式喂进去**：记忆、任务指令、下一步子任务指令、**标注数据质量与 episode 长度的元数据**，以及可选的子目标图像（部署时由一个世界模型生成，子任务由高层策略预测）。

消融是全场信息量最大的部分，两条：

- 去掉**最多样**的那一部分数据，留出任务上的性能断崖式下跌；而随机去掉 20%（多样性较低的那些）只掉一点。**多样性和数据量不是一回事。**
- **不带元数据条件时，把最后那 20% 低质量数据加进去，性能反而下降；带元数据条件时，同样这批数据加进去性能上升。** 也就是说，把「这条数据有多脏」作为条件输入告诉模型，是决定脏数据是负资产还是正资产的开关。

成品的表现：单个 π0.7 开箱即用，**追平或超过**那些为 espresso、为折箱专门做过强化学习后训练的前代专家模型（对纯监督微调的专家也成立）。组合泛化给了两个证据：一个是空气炸锅这类罕见电器（事后查全库只有 3 条相关片段），技能与物体的组合成立；另一个更值得注意——**跨本体**：在一台尺寸、连杆长度、关节构型都完全不同的工业臂上叠衣服，**该本体上没有任何折叠数据**，性能接近人类遥操作。

问答里还有两条：所有展示的模型输出的都是**目标关节角加夹爪的三维目标位置**，下面接 PD 控制器，直接出力矩或电压也可行但目前不是瓶颈；「想象未来图像」这个能力有可量化的增益，但比预期小，模型不带它也很强——她说本来打算就此单独写一篇技术报告，结果发现没有它模型也够好，就没写。

另外一个有意思的现象：装配纸风车时，训练数据里固定右手拿针、左手拿纸，某次出错后针和纸的左右位置互换了，机器人**自己换手完成了任务**——而这个模式在预训练和后训练数据里都不存在。左右手之间的等变性是学出来的，不是喂进去的。

### 5. SCoPE：把相机视线当成位置坐标喂给视频 DiT

[模型与代码（TencentARC，Apache-2.0）](https://huggingface.co/TencentARC/SCoPE)

给预训练的视频 DiT 增加「相机视线」作为位置坐标：输入首帧、文本和一条相机轨迹，输出跟随该相机运动的视频，同时保住原有的图生视频先验。基于 Wan2.2-I2V-A14B 的自包含发布，约 67GB 权重加代码，附在线 demo，Apache-2.0 许可。

需要说明的是，**这里只读到了模型卡，没能找到 SCoPE 本身的论文条目**（页面上关联的是前作 RayPE），所以方法细节未经论文核实，下面只讲模型卡上明确写了的东西。

真正可迁移的一点在训练数据协议上：它同时用了 RealEstate10K、DL3DV、PanShot、OmniWorld 四个数据集，靠一套**统一的相机协议**把它们对齐——位姿全部表示为相对第一帧，平移用**每段片段自己的近平面深度**做归一化，而绝对尺度不在数据侧解决，交给模型内部一个**可学习的 scale gate**。这是混合异构数据集时那个经典麻烦（不同来源的尺度不一致）的一种解法：不在预处理阶段硬对齐，而是归一化之后留一个可学的尺度旋钮。模型卡也老实列了退化条件：位姿或内参不准、轨迹远离训练分布、大面积遮挡、相机运动过快时质量下降。

### 6. Anthropic：能拆开的活越多越好，必须缝在一起的活越多越乱

[中文报道（量子位）](https://mp.weixin.qq.com/s?__biz=MzIzNjc1NzUzMw==&mid=2247912624&idx=3&sn=f6535d15478ea80f1cc9673c63a3deee)

与具身没有直接关系，但这是一份认真做了负面结果的研究，而「低方差」这个失败模式的可迁移性足够高。三条结论：

**任务能不能拆开，决定一切。** 找漏洞这类成果可直接相加的任务上，多智能体表现很好：45 个 agent 各配一台虚拟机加一个共享论坛，去查 15 个开源项目，共找到 **266 个**漏洞，而独立并行方案只找到 21 个，且两边只有 12 个重合——它们会自己造工具、共享线索、逐渐形成专精分工。但换成强依赖任务（10 到 80 个 agent 连续 12 小时合作开发一个网页开放世界游戏）就全面失败：80 个 agent 时两个模型分别开出 **876 和 980 个 PR**，大量互相冲突、真正合并的很少；表现「较好」的模型减少冲突的办法是**各管各的文件、少与同伴共享代码**——那不是解决了协作，是学会了回避协作。自由组队、预先分配角色、任命一个 agent 当「CEO」三种组织方式都没能改善。

**「低方差」比协作失败更值得记。** 同一个模型复制出来的 agent 彼此太像：30 个 agent 里有 18 个建了同名分支；让它们各自写小说，多个撞上同一个标题；让它们各做「令人印象深刻的东西」，超过一半选了光线追踪器或自举编译器，并且**在相似的位置遭遇相似的失败**。资源竞争时更糟：在一个带宽有限的任务队列里，它们各自开起每秒 30 次的高频轮询，一次实验产生 **240 万次请求而只有 117 个被接受**，集体把系统堵死。反过来，在本该竞争的定价博弈里，3 到 8 个 agent 到第 3 轮就商定了价格底线；研究者切断私聊通道也没用——它们靠公开报价牌互相跟价，把默契维持住了。

**群体讨论会压低正确率。** 在隐藏信息实验里，把全部信息交给单个 agent 独自决策，正确率接近 100%；一旦进入群体讨论，除一个模型约 85% 外，其余模型选中正确答案的比例只有 **17% 到 36%**——握着关键证据的少数派说服不了多数。

结论对任何打算用多智能体做长程任务分解的人都成立：**不要指望多个副本互相纠错**。同一个模型的副本给你的是相关的错误，不是多样性；真正能从「人多」里获益的是可加性任务。
