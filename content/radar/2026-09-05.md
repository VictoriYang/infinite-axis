## 1. Select, Compress, Reinvest：帧预算分配不是预处理细节

[arXiv:2609.03820](https://arxiv.org/abs/2609.03820) · [HuggingFace](https://huggingface.co/papers/2609.03820)

长视频模型没法看每一帧：一小时按每秒一帧采样是 3600 张图，系统只留其中固定的一小片。哪些帧活下来，通常被当作预处理细节处理掉。这篇要检验的就是这个默认假设。

它指出已发表的 selector 互相之间根本没法比较，因为它们同时改了四样东西：帧打分器、prompt 边界、分辨率策略、回答模型。于是作者把这四样全部固定，一次只动一个决策——**选帧、空间压缩、把省下的预算再投入**——在六条免训练选帧规则、三个长视频基准、两个回答模型上做受控对照。

三个结论都带数字：

- **选帧是最大的单一杠杆。** LongVideoBench 的小时级分档里，8 帧 query-selected 比 16 帧均匀采样高 6.9 分。也就是说少一半的帧、选得对，反而更准。
- **但最好的选帧规则不需要训练。** Orthogonal Matching Pursuit——一个几十年前的稀疏逼近算法，未作任何修改——在三个基准上追平、或落后不到 1 分于所有专门设计的 selector。
- **压缩几乎免费，但单独压是白压。** 固定时间戳下把每帧空间预算砍半，最多掉 0.44 分；可只有把省出来的 token 花回到「两倍数量的压缩帧」上，才再涨 2 到 3 分。压缩的收益只在被花出去之后才存在。

**它改变了什么。** 这个方向的默认动作一直是「学一个更好的 selector」，力气花在打分器的模型结构上。这篇把三个决策解耦之后，结论是选帧确实值得投入，但一个免训练的经典算法就已经踩在天花板附近——所以合理的顺序是先把 OMP 这类无训练规则打成基线，再判断学出来的 selector 到底有没有增量，而不是直接开训。同样地，压缩不该单独做，必须和「再投入」配成一对，否则省下的预算不会变成精度。

而最值钱的一段是作者的自我暴露：他们在自家的 AKS 基线实现里发现了一个 bug；并且**同一套已发表的规则、同一预算，在两个 harness 上跑出 0.07 到 3.74 分的差距**。3.74 分足以吃掉这类论文声称的大部分增量。这等于说，跨论文比较长视频的数字这件事本身不成立，比较必须发生在同一个受控 harness 内部。

## 2. AutoTraceGT：失败分类法可以从轨迹里长出来

[arXiv:2608.30391](https://arxiv.org/abs/2608.30391) · [HuggingFace](https://huggingface.co/papers/2608.30391)

要理解 agent 的行为，需要能扩展到上千条轨迹、并且能在陌生的长任务里发现新模式的方法——预先建好的分类器在这种场景下不够用。这篇的做法是把社会科学用了六十年的**扎根理论**（grounded theory）搬进来：一套带原则性**饱和判据**、并且保留从数据到理论的可审计链路的定性方法。

AutoTraceGT 是第一个把扎根理论自动化到 agent 轨迹上的多智能体流水线，迭代执行开放编码 → 轴心编码 → 理论编码，直到达到饱和才停，为每个任务产出定制的行为分类法。

关键在于它是**归纳的，不预设失败类型**。结果：在六个轨迹语料上，自动长出来的 codebook 复原了人工标注分类法里 **73% 到 91%** 的失败模式，同时还捞出了那些人工分类法漏掉的模式；浮现出的理论叙事与已有的专家论述吻合。反过来把这个 codebook 当作演绎特征空间用于下游失败预测时，效果好于 zero-shot 和 few-shot 的 LLM 基线。

**它改变了什么。** 在上万条轨迹里找失败模式，此前只有一条路：人先定义失败有哪几类，再训练或提示一个分类器去打标签，分类法的边界靠人反复调。这篇把顺序反过来了——让分类法从数据里归纳出来，并且用饱和判据而不是人的直觉来决定什么时候停止。对任何需要做大规模失败归因的系统（自动数据标注、失败恢复数据的质量控制），这意味着流程应该拆成两段：先归纳出 codebook，再拿它做演绎打标。

另外，73%-91% 这个数字反过来读更有信息量：**人工标注的分类法本身就漏掉了一到三成的失败模式。** 所以拿人工分类法当 ground truth 去评估自动打标的准确率，这个上限从一开始就是被高估的。

## 3. ScienceDiscovery：不训模型，只让产物在树上演化

[量子位报道](https://mp.weixin.qq.com/s?__biz=MzIzNjc1NzUzMw==&mid=2247918839&idx=2&sn=c888eb2ab4fcd88b5d1c8c8b178f4c73)（openJiuwen 社区）

科研里的常见情形是：写一个能算准振荡积分的程序、把一段数值代码调快十倍、从一张数字表里反推出背后的方程——第一版实现通常都不够好，主要工作量在其后的几十到上百次试错。这类工作的形式是搜索，不是单次执行。

这个系统把试错交给程序自己完成，被演进的是**科研代码本身**：模型不训练、搜索规则也不改，每一轮变的只有产物。搜索展开成一棵树，每版产物是一个节点，可以被再次选中改写并长出新分支，也可以先搁置、几十版之后再被捡回来继续改；得分高的分支获得更多改写机会。每轮四步：选一个父版本 → 交模型改写 → 进沙箱评分并挂成新节点 → 把这次访问记账到它的全部祖先上。**运行失败的版本同样入树，标记为失败。** 沙箱隔离崩溃、死循环和超时，因此不必对模型生成的代码预设任何限制。

四个案例都摊开了曲线和绝对数字：

- **半无穷区间上的振荡积分**（通用积分器在这里失灵，因为它靠局部误差估计决定加密采样，而这些函数振荡不停）：题面和答案全程不可见，唯一反馈是精度分。直接调 `scipy.integrate.quad` 得 −3.40——19 道里只有 3 道进入 3% 容差，最差一道与真值差约 24 亿倍。搜到第 119 版得 −0.0007，19 道全部算准、平均相对误差 0.07%。全程 2 小时、236 个版本、无人干预。最终那份 247 行的程序会先判断被积函数在何处发散、振荡多快，再分情况选算法，因此在未参与打分的另 19 道上同样有效。
- **高斯超几何函数 ₂F₁ 的双精度求值**（公认没有单一算法覆盖全参数域）：48 次扩展、598 秒，1000 个从未见过的点上平均正确位数从 9.836 升到 11.771。拆开程序能看到它找到了什么：z 小于 −1 时标准算法不收敛，搜索找出一条经典恒等式把 z 换成 1/z 避开这一段，并自行确定了切换条件。
- **AlgoTune 代码加速**（154 个来自 numpy/scipy/networkx/cvxpy 的真实任务，得分是相对参考实现的加速比）：平均 2.279 倍。作为对照，官方榜最高的 claude-opus-4.6 是 1.837，而**先用强化学习训一个模型的 MetaEvolve 是 2.045**。提示词里没有点名任何加速技术。
- **从观测数据反推方程**（LLM-SRBench 的 LSR-Transform 子集，只给一张 4000 行的纯数字表）：111 道里 41.4% 写出了正确方程，每题平均只有 16.5 次模型调用。

**它改变了什么。** 「自进化」这个方向的宣传稿远多于实证，而愿意报出每轮得分曲线、版本数、模型调用次数和成本的更少。更值得注意的是 AlgoTune 那组对照：现成模型加树搜索得 2.279 倍，高于先训了一个模型的 MetaEvolve 的 2.045、和榜首单模型的 1.837。这至少说明在这类任务上，**涨点不必来自训模型**——被演进的对象可以只是产物，权重和搜索规则都不动。对任何想搭技能库或自迭代流水线的人，这把优先级调了个头：先把「产物可被反复改写 + 沙箱自动打分 + 失败版本也入树」这套搜索结构调通，再讨论要不要训策略。

失败版本入树而不是丢弃也是个可以直接抄的细节。常见做法是把失败轨迹过滤掉，而在树搜索里它们是负例分支，能阻止后续版本重走同一条路。

## 4. OpenART Arena：把环境状态本身纳入评测

[arXiv:2608.00677](https://arxiv.org/abs/2608.00677) · [代码](https://github.com/AI45Lab/OpenART) · 复旦大学 / 上海人工智能实验室 / XSafeAI · [中文解读](https://mp.weixin.qq.com/s?__biz=MzIwMTc4ODE0Mw==&mid=2247722656&idx=2&sn=c8680371c9d7849813a0c16942fa7368)

Agent 进入真实工作流后，文件、工具结果、权限、记忆和计划状态会在后续步骤里被反复读取与修改，一个早期的变化可能沿着长程执行一路传播，直到很多步之后才表现为安全失效。现有的 agent 安全基准大多建在相对固定或可重置的环境上，很难覆盖这种状态累积与跨步骤传播。

OpenART 把评测单位换成**完整的可执行场景**：测试过程中良性任务目标和隐藏的安全约束保持不变，变化的是 agent 实际能看到和使用的环境状态。三处设计值得单独看：

- **让长程任务真的可执行。** 从 50 万以上的 Tools、MCPs 和 Skills 能力库出发，在 50 个应用领域构造并验证了 1 万以上有状态场景，每个都要通过执行检查和 Evaluator 验证才进测试集。**任务所需工具调用次数的中位数是 97**——这个长度才让前面产生的状态有机会在后续流程里被继续读取、组合和修改。
- **让同一个场景适配不同 Agent。** 先用一种 target-agnostic 的方式描述场景，再通过轻量 Adapter 把相同的任务目标、安全约束和 Evaluator 映射到各个 agent 的原生 harness，覆盖 15 个已部署 agent × 5 个基础模型 = 75 种配置。这样基础模型的差异、agent 实现的差异、接口的差异才能被分开看。
- **把环境状态纳入搜索。** 每轮从当前环境和历史攻击状态出发生成一组候选环境变化，经目标 agent 的 Adapter 检查、只保留该 harness 支持且允许修改的 state surface 才真正写入。支持八类 state surface：Workspace、Instructions、Skills、Tools、MCPs、Short-Term Memory、Plan State、Long-Term Memory。参考搜索方法 EMHA 用 black-box 反馈，target 模型和 attacker 模型的参数都不动，适应过程发生在外部的 attacker state 里。

**它改变了什么。** 把它和本期第一条放在一起读最有意思：第一条抱怨的是同一套规则在不同 harness 上不可比，而这里的 Adapter 结构正是这个问题在评测框架层面的一个答案——先把任务目标、安全约束和 Evaluator 固定成与实现无关的描述，再往各家 harness 上映。另外，把 Plan State 和长短期记忆明确列为**可被污染的 state surface**，等于承认长程系统的记忆是攻击面而不只是能力；这一维在多数长程任务评测里根本没有被单独暴露出来。

## 5. Eureka：在执行中动态「生长」专用子架构

[arXiv:2608.19047](https://arxiv.org/abs/2608.19047) · 广东工业大学 / 华南师范大学 / 上海交通大学 / 杜克大学 · [新智元报道](https://mp.weixin.qq.com/s?__biz=MzI3MTA0MTk1MA==&mid=2652722736&idx=3&sn=e59b69e8c62060cf1751a9e761120c28)

**需要先标明来源限制：** 本轮拿不到这篇的 arXiv 正文，以下内容与全部数字均来自中文报道所述，未与论文核对。放进来是因为它触及的问题（长程任务里的自我验证）在本期是唯一一条，但读者应把数字当作待核实的转述。

当前的 agent 系统，其架构——记忆、工具、验证方式、内部协作流程——通常是提前设计好的。报道给出的论点是：这在单一类型问题上效率很高，但科学发现是长周期、高不确定性、结构各异的过程，一个固定架构会撞上两类问题：架构错配（擅长广泛搜索假设的架构在做严格数学证明时因状态同步成本过高而低效），以及规划失效（任务初期未来步骤充满未知，提前做完美长期规划既费算力又容易被中途的新发现推翻）。

Eureka 的做法是把「任务执行」和「架构塑造」合成一件事。接到复杂任务后先编译成一张**动态义务图**，只规划当前信息能够确定的部分，其余留待以后。执行中如果发现某部分任务反复使用相同的状态、工具或需要紧密协作，就识别出一个「架构热点」，并对它做**架构提升**——为这个热点编译出一个全新的专用宏代理，带有自己的记忆、工具箱、验证标准和内部工作流程，主系统只等它给出最终的可验证结果。当宏代理反复遇到同一类瓶颈时，会先评估改造收益是否高于成本，只有确定更高才升级其内部结构。

报道所述结果：完成全部 170 项复杂递归长周期任务，生成 3948 份可验证的合格证书，**过程中没有出现一次错误的自我肯定或虚假的任务完成**；把语义规划与确定性计算分离后，核心工作区的上下文负担降低 57.8%，避免了 65.38% 的重复计算；在 16000 项任务的并发测试中，并行执行结果与顺序执行一致。在具体问题上，报道称它在黎曼猜想的局部 Weil 二次型正性这条路径上把关键证书的适用范围从 a ≤ 1/4 扩展到 a ≤ 69/200（0.345）。

**为什么值得记一笔，以及该保留多少怀疑。** 「零次虚假任务完成」如果站得住，恰好是自迭代系统最缺的那一环——任何让系统自己生成失败数据、自己决定要不要重试的设计，前提都是它能诚实判断自己失败了。但这也正是转述中最容易被润色的一类断言：3948 份证书由什么验证器判定、这个验证器能否被 gaming，报道里没有交代。这条的正确状态是「待核实的重要线索」，不是结论。

## 本期主动检索的结果，以及一条要说明的空白

除了当日抓取，本期还带着三个固定问题做了主动检索（不限发布时间），分别是：推理时学习在具身侧的进展、长程任务里的记忆机制、跨本体动作表示统一到了什么程度。

**前两个问题 0 命中，需要如实说明。** 「推理时学习」的检索退化成了离线强化学习里的 evaluation-time policy switching、高斯过程在线模型学习、以及 2018 年前后的自适应控制，没有一条触及当前基线（把测试时训练层装进机器人基础模型）尚未验证的那几点：跨本体迁移下是否还成立、wall-clock 延迟的实测数字、超出上下文长度后的遗忘行为。「长程任务的记忆」这一问的候选也都不满足判据——用外挂语言模型维护状态的方案被判据明确排除，轨迹引导与经验检索类工作没有对「记不住」这件事做失败率归因。

**第三个问题命中一条，但没能写进来。** MOTIF（[arXiv:2602.13764](https://arxiv.org/abs/2602.13764)）对跨本体迁移主流的 shared-private 架构给出了直接批评——私有参数容量有限、且缺乏显式的适配机制。这正是这个问题想要的那类证据。但它的正文这次仍然拿不到（本轮站外抓取整体失效），而按不脑补的规矩，读不到正文就不写摘要。**这已经是它第二次因为同样的原因落选**，记在这里既是提醒也是备案。

顺带记一条没入选的：Om AI 的 VLX-VR 报了 MINERVA 78.8% 登顶，并且给出一条反常的时长曲线——5 分钟以下 76.70%，15 分钟以上反而升到 80.92%，而同档的 Gemini 2.5 Pro Thinking 从 68.87% 跌到 57.97%。数字很吸引人，但这是厂商自述、没有论文，**并且没有披露任何帧选择与压缩策略**。而本期第一条刚好证明选帧是最大的杠杆、同一规则跨 harness 能差 3.74 分。在选帧策略不公开的前提下，「越长越准」最简约的解释是采样与 harness 的混杂，而不是推理能力上的突破。这条留待有方法披露时再看。
