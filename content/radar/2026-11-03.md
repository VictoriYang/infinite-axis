## 1. RoboArchitect：把 harness 本身当成被优化的对象

[论文](https://arxiv.org/abs/2610.42141)

前提是一个已经被反复观察到的现象：一个冻结的机器人策略，放进 agent harness 里（由控制代码决定什么时候查询策略、什么时候调用视觉工具、什么时候直接给机械臂发指令）会比裸跑强得多。问题在于这些 harness 现在全靠手写，换一个机器人、换一个 benchmark 就得重做一遍。

这篇把 harness 的设计本身自动化了：一个 coding model 观察机器人的 rollout、诊断失败、迭代改写包在冻结策略外面的 harness。harness 在一批 episode 上优化，在留出的场景和任务上评测。

数字很硬，而且**全程不更新任何模型权重**：未见场景的平均成功率从 9.7% 到 43.3%（4.5 倍），未见任务从 12.7% 到 40.2%（3.2 倍），跨多个 benchmark 和多个策略都成立。更值得注意的是增益的分布规律——**benchmark 离策略的训练分布越远，harness 带来的增益越大；把一个通用策略包起来，演化出的 harness 常常比在该设置上 finetune 过的版本还强。**

演化出来的控制策略是人能看懂的那一类：机械臂卡住了就抬起来脱离，上方被障碍挡住就改成水平伸入。harness 还会演化出自己的持久记忆，把学到的经验（比如某类物体的有效抓取深度）带进后续决策。

**它改变了什么。** 过去遇到新场景或新本体，默认动作是拿那边的数据去 finetune 策略权重，而 harness 被当成一次性的手工脚手架，写完就不管了。这篇把顺序倒过来了：先固定策略权重、让一个 coding model 跑几轮 rollout 诊断失败并改 harness，把这个结果当成 finetune 的基线——finetune 要证明自己比它强，才值得花那份算力。考虑到「演化出的 harness 常常打赢 finetune 版」，这个基线并不是形式主义。

## 2. REA：没有任何正在运行的策略需要等大脑

[论文](https://arxiv.org/abs/2610.42053)

「慢的大脑 + 快的小脑」这个结构几乎所有人都在用，但这篇把现有写法的故障模式说得很具体，而且其中一个容易被漏掉：**在 agentic loop 里调用 VLA，会让快速执行停等；反过来让 VLA 在出错时去叫 agent，则会反复触发同一个 fallback，并且完全漏掉静默失败**——也就是那种策略执行偏了但没有报错、所以永远不会触发 fallback 的情况。另一个问题更现实：这类方法各自建在互不兼容的栈上，分数之间没法比。

REA 是一个统一运行时，让慎思的 System 2、做路由的 System 1 和反应式的 System 0 策略在一条硬规则下协作：**没有任何正在运行的策略需要等大脑。** 落地成三件事——route memory 事前量好每条策略在各任务上的成功率（而不是每次失败才去问大脑）；边界触发的 judge gate 只在一段策略执行的边界上咨询大脑；共享预算的升级阶梯让恢复过程有界，不会无限重试。

在 3000 个测试 episode、60 个 LIBERO-Pro 任务上达到 95.9%，高于它自己策略池里最强的单 agent 基线（94.7%），同时**控制步数降低 25%、控制时间降低 17%**。另一组 100 episode 的 RoboTwin 2.0 实验：纯 VLA 策略 84%，VLA 加上代码策略 86%，而最强的单 VLA 基线是 80%。方法还迁移到了 BEHAVIOR-1K 和真机 Unitree G1 人形机器人。

**它改变了什么。** 「失败后回头问大模型」这个 fallback 写法的延迟代价，之前是作为既定成本被接受的。这篇的结果说明那份成本本来就付得过多了——改成边界触发加事前量好的路由表之后，控制步数和时间都降了，成功率反而上去。更有价值的是它点出了静默失败这一类：以失败为触发条件的恢复机制，结构上就覆盖不到没有报错的失败，而这部分在长程任务里并不少。

## 3. WorldBridge：动作标签在「每任务一条」就基本吃满了

[论文](https://arxiv.org/abs/2610.40748)

这篇最有价值的部分不是模型，是模型之前那个受控实验。它在 RoboTwin 2.0 上把「视频泛化」（预测新任务的视觉演变）和「动作泛化」（把预测翻译成可执行行为）的贡献分开量化：

- 只用分布内的视频-动作监督，分布外任务成功率 **25.07%**
- 把这些分布外任务的视频加进来，**不带任何动作标签**，涨到 **55.90%**
- 再给每个任务加**一条**带动作标签的示范，涨到 **70.70%**

作者的解释是：更广的视频覆盖面激活了模型已经具备的逆动力学能力，而稀疏的动作监督进一步加固这份能力。

模型侧 WorldBridge 是分离的 video expert 与 action expert，通过结构化注意力连接、用联合 flow matching 训练，带两个时间尺度的视觉记忆和 action forcing，外加一条把异构机器人轨迹与第一人称手部衍生监督统一标准化、过滤的数据管线。RoboTwin 2.0 全量设置 96.23%，clean 到 random 设置 80.9%，RoboCasa GR1 TableTop 82.8%，DOMINO Level-1 57.6%。

**它改变了什么。** 「给新任务补视频」和「给新任务补动作标签」通常被放在同一个优先级上排采集预算，默认两者都贵。这个三段拆解说明它们差着量级：大头在视频覆盖面（+30.8 个百分点），动作标签在「每任务一条」这个量级就吃掉了大部分剩余（+14.8 个百分点）。对任何要给新任务铺数据的团队，预算分配的默认值该倒过来——先铺不带动作标签的视频，动作示范从每任务一条起步，而不是从每任务几十条起步、把视频当附属品。

## 4. RSI-Nav：执行轨迹负责验证，原始轨迹负责监督

[论文](https://arxiv.org/abs/2610.15782) · [代码](https://github.com/OpenGVLab/RSI-Nav) · 复旦 / OpenGVLab

> 本轮只读到前 2000 字正文（全文 2794 字）。两个核心设计和主结果表都在这一段里；消融部分截断，下面不涉及。

基于 Qwen3.5-9B，用任务 prompt 把三件事放进同一个模型：根据视觉历史和指令预测动作（VL2A）、根据沿途图像和动作生成路线指令（VA2L）、以及方位与地标的空间理解。三者共享参数，不另外训练 Speaker 或专用输出头。理由讲得通：描述一段路线需要辨认沿途地标、转向和终点，而这些恰好就是把指令落地为动作所需的视觉语义。

然后是 Policy-Synchronized Dual Bootstrapping。对每一批无标注轨迹依次做四步：Generate（根据视觉-动作轨迹生成导航指令）、Execute（从起点执行该指令）、Filter（依据是否抵达目标与路径效率筛选）、Update（SFT 更新后处理下一批）。它指出过去离线数据飞轮的两处断点：指令生成与导航执行分属不同模型、双向知识不互通；离线合成数据跟不上策略的变化，形成 policy gap。

结果（R2R-CE 与 RxR-CE 的 Val-Unseen，**只用第一视角 RGB**，不用深度、里程计或外部 waypoint predictor）：R2R-CE 从 52.9% 到 68.6%（+15.7 个百分点），RxR-CE 从 54.7% 到 72.4%（+17.7 个百分点）。同时 SPL 从 45.5% 到 58.6%、nDTW 从 62.4 到 70.6，说明涨的不只是「到了终点」，路线执行质量也在涨。累计构建约 250 万条导航训练样本和 110 万条指令生成样本，开源。

**它改变了什么。** 自生成数据的流程里有一个容易顺手犯的错：拿执行出来的那条轨迹既当验证、又当监督目标。这篇把两者明确分开——执行轨迹只负责判定「这条生成的指令是否可用」，动作监督一律用**原始参考轨迹**，理由是试走时的动作偏差不该成为学习目标，否则模型是在学自己的抖动。第二点是它不上强化学习，只做分批、每批立刻 SFT 更新，靠「生成和验证都由当前模型做」来压 policy gap（作者自称 Policy-Synchronized 而非严格的 on-policy）。两点都是可以直接照搬的配方级细节。

## 5. Cortex：把「学会了」和「换掉了旧能力」分开报

[论文](https://arxiv.org/abs/2610.20399) · [代码](https://github.com/zjunlp/cortex) · 浙大 / ByteDance Seed / 清华

> 本轮只读到前 2000 字正文（全文 16205 字）。这一段覆盖了问题形式化、两个指标的定义和工程可用性；**具体方法与结果表未读到，下面不涉及这两部分。**

问题设定做得很干净。用 Context（记作 C）作为经验的统一载体——它可以是一份工具文档、一段交互经验的总结、一组修正后的事实，或一段行为指导。先比较同一个模型在有 C 与无 C 时的表现差距，这个差距被称为 **context gap（上下文收益）**，它为「这段经验究竟能教会模型什么」提供了一个可观测的参照。再引入两类评估：**Q⁺** 查模型是否学到了预期的变化，**Q⁻** 查本次学习之外的能力是否保留。目标（Memory Consolidation）是找到一种更新方式，使模型**在不再访问 C 的情况下**仍能恢复 C 带来的收益，同时保住预期改变之外的能力。

两个配套指标：**巩固率 CR** 等于更新后不带 C 的目标增益除以原模型带 C 的目标增益；**保留率 RR** 等于更新后在 Q⁻ 上的表现除以原模型在 Q⁻ 上的表现。两者都可能超过 100%。这个定义只规定「什么算学成功」，不预设训练算法，而且留出的评测问题不会交给方法去训练。

工程上，Cortex-Structural 已经合入 Hugging Face 的 PEFT 库，支持兼容的稠密模型与 MoE 模型。团队补充的实测数字：120B 模型在 ALFWorld 上沉淀 agent 经验，8 张 A100，参数训练约 30 分钟。

**它改变了什么。** 这里真正可迁移的不是方法而是**口径**。持续学习和技能入库类方案通常只报「新任务涨了多少」，但这一个数同时包含了两种完全不同的情况：真的学会了，和把旧能力挤掉换来的。CR 与 RR 这对比值把它们分开了。按这个口径，只报新任务增益、不报保留率的结果应当按不可比处理——这是一条可以立刻用起来的审查标准。

## 6. CaPtain：让策略本身是一个写代码的 agent

[论文](https://arxiv.org/abs/2610.40799)

现有的 code-as-policy agent 全都绕开了训练这一步：要么 prompt 闭源前沿模型，要么把实际操作委托给预训练 VLA 和高层技能，而小的开源视觉语言模型直接就不 work。CaPtain 是一条开放的后训练流水线，把小的开源 VLM 变成可用的 code-as-policy agent，**测试时不用 VLA、不用前沿模型、不用特权状态**。策略在 CaPtain-Harness 里训练和部署，harness 暴露底层感知、几何和带保护的运动原语，仿真与真机共用一套。

配方是从 coding / web agent 那边直接搬过来的：先用合成轨迹做 SFT 对齐接口，再做多轮强化学习掌握接口。真正的难点在 credit assignment——多轮 RL 要从单个 episode 末端的一个结果，去归因几十次 agent 请求，而这些请求的物理后果往往要好几轮之后才显现。它的做法是引入一个**物理 critic**，读取策略永远看不到的特权仿真状态，按「这次请求把预测成功概率改变了多少」给每一次请求记账。

从 Qwen3.5-4B 起步（零样本 0%）：SFT 后 LIBERO held-out 55.4%，RL 后 73.8%；LIBERO-PRO 上 78.5%，超过若干前沿模型 agent；RL 带来的增益在三套扰动集上都保住了（+17.6 到 +21.2 个百分点）。无目标域训练的情况下 SimplerEnv WidowX 83.3%，CaP-Bench 上超过前沿模型，纯仿真适配后能上真机。代码、数据、权重全部放出。

这是本期主线的第三种答案：与其训一个更大的 VLA，不如让策略本身就是写代码的 agent，然后用语言 agent 那套成熟的后训练配方去打磨它。

## 7. CausalWAM：只有一部分场景是动作的成因

[论文](https://arxiv.org/abs/2610.42096)

指出世界动作模型（WAM）的一个结构性漏洞：预测这件事必须覆盖整个场景，但**只有场景的一部分是动作的成因**。拿示范拟合出来的 WAM 并不保证它只从「动作相关隐变量」生成动作——它完全可以一边模仿得很好，一边把动作相关隐变量和无关的 nuisance 变量缠在一起。

这篇把「什么导致动作」和「预测依赖什么」分开。理论部分证明：在一个稀疏性约束下，用于生成动作的隐变量是**动作相关隐变量单独的可逆函数**，真实结构在隐变量置换意义下可辨识；而且这个结论**既不需要充分的时间依赖，也不对未观测 regime 如何演化做任何假设**，即使动作相关隐变量与其余变量统计相关也成立。

方法上的代价很低：往预训练 WAM 的 action head 加一条**稀疏路由路径**，世界建模目标完全不动。合成数据和真机都验证了理论，闭环成功率的效率也有提升。对已经有一套 WAM 或者 action expert 接在共享 backbone 上的人，这是一个几乎不需要重训就能试的约束。

## 8. ReLift：稠密 3D 跟踪其实不需要联合训练

[论文](https://arxiv.org/abs/2610.42136)

单目视频做稠密 3D 跟踪，通常把三件事一起学：建立点对应、估计深度、推断遮挡期间的轨迹。而 4D 监督非常稀缺，这个联合目标因此很吃力。

这篇先给出一个基线事实，本身就足够有信息量：**把成熟的 2D tracker 的轨迹用 3D 几何模型抬升、遮挡段只做简单插值，在同样的几何下已经能打平专门的 3D tracker。** 剩下的问题是抬升轨迹会继承对应与深度的误差，而且遮挡时它的深度来自遮挡物而不是被跟踪的那个点。

于是 ReLift 把稠密 3D 跟踪重写成「几何轨迹的修补与补全」：一个 trajectory corrector 在「沿轨迹」和「跨轨迹」两个方向上交替做注意力，保留可靠的观测、修正被污染的位置、补全缺失的运动。因为只吃几何输入，它可以**直接在带模拟抬升误差的 3D 轨迹上训练，与图像、与具体 tracker、与具体几何模型全部解耦**——换 tracker 或换几何模型都不用重训，还能直接吃它们未来的进步。WorldTrack 上平均精度 SOTA，全部点 +2.1 APD、动态点 +3.0，更快的配置仍与领先 3D tracker 竞争。

对正在搭自动标注管线的人，这个解耦性质比那几个点的精度更值钱：标注工具链换代不意味着修补模型要重训。

## 9. Metis-1.6：一份把「出了什么错」当成主体的技术报告

[论文](https://arxiv.org/abs/2610.37903)

一个人从零做的两个语言模型（Praxis 2.94B 参数、每 token 激活 0.46B；Logos 10.23B、激活 1.18B），Mamba-2 与注意力混合的 MoE 栈对每个 token 跑两遍。各训了 1.02T token。40 个后训练 benchmark 上 Logos 平均 52.93 分，17 个模型里第七，和 Qwen3-4B 差不到一分——但**用的训练数据大约是那些披露了数据量的对比模型中位数的十二分之一**，每 token 激活参数少于任何打赢它的模型，两个维度上都落在 Pareto 前沿。数学第 2/30（AIME 2025 67.50%，HMMT 2026 二月 63.64%）；代码、指令跟随、长上下文都弱，作者自己写明了。

真正值得读的是作者自称最有价值的那部分——**出了什么错**：他配置的 optimizer 从来没真正跑起来，注意力在整个预训练期间都是 AdamW 训的；一个 1.77B 参数的 n-gram memory 学会了**把自己关掉**；五个微调选择损失了能力；以及**在组均值归一化下，长度奖励一旦某组通过率超过 2/3，就会反过来惩罚正确但较长的解**——他给出了这个符号反转的证明，并用一行 clamp 修掉。

最后一条值得任何在做 GRPO 式分组归一化加长度奖励的人立刻去自查：这类 reward 的符号通常被当成组内一致的，而它实际会随组通过率翻转。这种把失败模式连同证明一起写出来的报告，可迁移性比又一个 SOTA 高得多。

## 10. 训练-推理 mismatch：一个可直接用的监控量

[论文](https://arxiv.org/abs/2610.40945)

on-policy 强化学习假设训练响应来自当前策略，但实际情况是推理引擎负责采样、另一个 trainer 负责算梯度，两者之间的 mismatch 让数据变成了 off-policy。这篇把 mismatch 拆成两个来源，并指出一个关键事实：**修好其中一个的校正，会在另一个上失效。** 两个来源是引擎的数值差异，和异步采样造成的陈旧权重。

做法是在采样器的权重上评估 trainer，把每个采样 token 的误差**精确拆成**引擎的数值差异和 trainer 的 policy lag，然后跟踪两者在整个训练过程中的演化。结论相当具体：数值差异近似恒定，因此以几乎固定的量偏置更新，在每个 prefix 上做 score centering 就能去掉主导偏置；而 policy lag 是 trainer 自己的更新造出来的——它留下的偏置进入下一次更新、放大下一次 lag，闭成一个反馈环。重要性加权只在 lag ratio 保持集中时能切断这个环，在 Qwen3-1.7B 上，**它失效的那一步恰好是 ratio 的有效样本量掉到二分之一以下的时候**。

由此得到 DLC：centering 数值差异、对着采样器权重裁剪 lag ratio、有效样本量低于二分之一时重新同步采样器。在陈旧采样器下，DLC 把与 on-policy 训练的 KL 控制在「两次独立 on-policy 训练之间的 KL」的两倍以内；它的重新同步避免了 per-token 校正留下的崩溃，**而这类崩溃是在采样器 prefix 上测的 KL 检测不到的**。

对任何在跑异步 RL 的人，这里有两样可以立刻拿走的东西：一个监控量（lag ratio 的有效样本量低于 0.5 就重新同步），和一个警告（在采样器 prefix 上测 KL 会漏掉即将发生的崩溃）。
