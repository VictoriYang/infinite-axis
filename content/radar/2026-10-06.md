## 1. PPO 后训练 flow-matching VLA：视觉增强只能加在 critic 上

**How (and How Not) to Use Data Augmentation in VLA Post-Training** · [arXiv](https://arxiv.org/abs/2610.05994)

埃因霍温理工（Bram Grooten、Joaquin Vanschoren），RoboPAD workshop 论文。问题很窄：用 PPO 后训练 flow-matching VLA 时，视觉增强应该加在哪一侧。设置是 RLinf 框架 + Flow-SDE，π0.5 和 GR00T N1.5 从 LIBERO-Spatial 的 SFT 权重起训 300 轮，骨干冻结只训 action expert 和 value head，在 LIBERO-Plus 的 1662 个分布外任务上评测。

结果很干脆。actor 和 critic 都加增强，π0.5 分布外成功率 0.1%，训练直接崩；只加 actor，4.3%，100 轮就停了；不加增强 73.9%；**只给 critic 加增强，81.7%**，其中相机扰动一栏从 45.7 到 55.1，噪声一栏从 40.7 到 67.8。GR00T N1.5 同样：actor 侧增强归零，critic-only 从 66.0 到 76.0。作者给的机制是：增强后 actor 输出的坏动作太多，PPO 的 clip 把大部分更新都剪掉了，等于没在学；而 critic 侧的增强只通过更好的 advantage 估计间接作用于 actor，不会破坏策略本身。

第二个发现是增强类型不可叠加。π0.5 上 overlay（贴图叠加）81.7、shift（随机平移）78.9、两者都上 75.9；GR00T 上 shift 76.0、overlay 66.0（一分不涨）、两者都上 69.0。两个模型最弱的分布外轴不一样，该选的是戳中那根轴的增强——overlay 对应外观和噪声，shift 对应相机和布局。overlay 强度有单峰，但任何强度都好过不加。

这篇改变的是一个默认配方。视觉 RL 里 DrQ 那套「actor 和 critic 一起增强」被当成标准做法沿用到 VLA 后训练，这篇量化出来在 flow-matching 策略上是反的，而且不是掉几个点而是归零。做 RL 后训练之前，先在 SFT 权重上跑一遍分轴的分布外评测找最弱轴，再据此单选一种增强、只加给 critic。代价是每步多一次骨干前向。没有真机。

## 2. 长动作块的失败集中在子技能切换点，异步执行消不掉短块的空转

**When to Switch: Reliable Action-Chunk Extension for Vision-Language-Action Models (RACE)** · [arXiv](https://arxiv.org/abs/2610.05719) · [代码](https://github.com/Seonghoon-Yu/RACE-VLA)

KAIST / GIST / NVIDIA / POSTECH。先做了一个诊断：把 π0.5 的动作块拉长后，误差不是均匀地随开环步数涨，而是**集中在子技能切换点**——用 PELT 变点检测自动标出切换位置，误差尖峰就落在那里，且随块长 K 增大。方法由此而来：在缓存的 VLM 特征上加一个「切换时机」预测头，用一次辅助的一步去噪得到位置先验，再对动作 token 做逐去噪步的可学习门控调制（门控权重随去噪步衰减）。

RoboCasa-H50 上，直接微调到 K=10/15/20 是 65.0/64.2/60.8（基线 K=5 是 60.4），拉到 20 已经比不拉差；RACE 在 K=15 到 67.3，拿到 2.9 倍提速还涨点。消融里有一个很硬的证据：推理时把切换先验整体平移一步，成绩（30.2–30.7）比把先验置零（31.8）还差——模型用的是「切换发生在哪」这个精确位置，不是「有没有切换」的粗信号。

真机部分最值得看。50 次 pick-place，所有配置都开着异步 RTC：微调 K=5 成功率 36%、每回合空转 2.11 秒；微调 K=20 成功率 48%、空转 0.40 秒；RACE K=20 **66%、0.41 秒**。完成时间几乎不变，因为异步已经把推理延迟藏起来了；但空转时间差 5 倍——异步执行本身并不能消掉短块带来的等待，只有长块能，而长块要能站住。

这篇改变的是对「块长怎么选」的框架。此前默认长块等于开环漂移，解法是自适应截断（AutoHorizon、PACE 那一类，本篇也都比过）。这篇说失败是局部的、可预测的，所以方向应该反过来：把块拉长、在切换点条件化，而不是整体缩短。另一个结论是「上了异步就不用管块长」不成立，空转那 2 秒异步兜不住。

## 3. VLA 推理的系统级刻画：观测过期的耐受度是模型属性

**Beyond LLM Serving: Characterizing Vision-Language-Action Workloads for Real-Time Robot Control** · [arXiv](https://arxiv.org/abs/2610.05062)

KAIST（Jaehyuk Huh 组）。四个模型（GR00T N1.6、π0.5、OpenVLA-OFT、Cosmos-Policy）乘三个平台（RTX 4090、Jetson Thor、Jetson AGX Orin）的系统刻画，闭环部分在 MuJoCo LIBERO 跑了 43,200 个 episode。几组可以直接拿来用的数字：4090 上单次推理 117–396 ms（2.5–8.5 Hz），Orin 上 304–2603 ms（0.4–3.3 Hz）；torch.compile 的收益在 action head 主导和骨干主导的模型之间差 5 倍以上；去噪头的 GEMM 落不落在 memory-bound 区由动作张量的维度决定（4090 的 ridge 在 163.9 FLOP/B）；DVFS 在 Orin 上省 24–32% 能耗，在 Thor 上只有 1–4%，压内存带宽则没有任何好处。

闭环实验把推理和执行的重叠比例从 10% 推到 50%：成功率下降、单回合耗时下降、总能耗上升，这三条趋势所有模型都一样。但**精度退化的幅度是模型属性**——π0.5 对观测过期最耐受，OpenVLA-OFT 次之，GR00T N1.6 和 Cosmos-Policy 最差，最多掉 56 个百分点；而速度增益反倒跨平台不变（GR00T 2.8–3.0 倍，π0.5 3.6–3.9 倍），能耗变化又是平台相关的。没有一个配置 Pareto 占优，但在所有 25 分位的延迟 / 能耗预算下选出来的都是 π0.5。

这篇改变的是「异步重叠比例可以当成一个通用部署参数」这个想法。它是模型属性，换模型就要重测 staleness 曲线。另外 action expert 的张量形状先决定了它是 memory-bound 还是 compute-bound，这比「加大 batch」更先决定该做哪种优化。

## 4. 自进化数据飞轮：策略不跟着更新，第二轮产出就归零

**InterMimicGen: Scaling Humanoid Loco-Manipulation through Self-Evolving Synthesis** · [arXiv](https://arxiv.org/abs/2610.06850)

UIUC + NVIDIA（Sirui Xu、Yu-Xiong Wang、Liang-Yan Gui），HuggingFace Daily 上榜。结构是：编辑人-物交互参考 → 用 tracker 在仿真里验证 → 留下成功的 → **用成功的回头微调 tracker** → 下一轮。这是近期少见的把飞轮每一轮的数据表完整放出来的工作：5 轮下来数据量从 20 倍涨到 142–150 倍，tracker 在生成参考上的成功率从 52–64% 到 98% 以上，原始参考保持 100%；质量指标在缓慢漂移（脚滑 1% 到 2%，手部抖动 1.00 到 1.17），5 轮内没有饱和。

最关键的是一张对照表：**tracker 冻结不微调时，第 1 轮产出 29.4%，第 2 轮 0.4%，第 3 轮 0.4%；微调的那条线是 25.3% / 72.9% / 68.9%。** 作者的话是「更多采样不能替代学习」——固定策略能通过的那部分编辑，第一轮已经采完了。真机在 Unitree G1（SONIC 控制器，50 Hz）和一台轮式移动操作平台上。

这篇改变的是对「飞轮最小可行形态」的判断。「生成 → 用固定策略筛 → 入库」这种先跑起来再说的做法，在这组数据里第二轮就停转。每一轮必须把策略也更新回环，飞轮才是飞轮。它同时给出了一个可以照抄的健康指标：每轮产出率、每轮的质量漂移、什么时候饱和——三个都报了，而「我们有一个自进化系统」的 PR 稿一个都不报。

## 5. 把时间分辨率也变成跨本体对齐的维度

**Vela: Scaling Vision-Language-Action Models with Adaptive Action Curve Representations** · [arXiv](https://arxiv.org/abs/2610.05230)

完全沿用 π0.5 的架构（3B PaliGemma + 300M action expert，不加参数），只改动作的表示：输出三次 B 样条的控制点而不是逐步动作，固定控制点预算，**曲线覆盖的时间跨度随运动复杂度变化**——取在噪声感知容差下投影误差达标的最长一段，训练目标在线构造。跨本体部分：共享动作空间定义为每臂末端平移 / 旋转 / 夹爪 + 头 / 腰 / 底盘，每一维有有效性掩码，每个数据源做仿射分位数归一化。loss 用解码后加权的 DT-FM 而不是直接在控制点上做 flow matching。一个负面结果值得记：先逐步预测再事后拟合样条不够，要训练时就在曲线空间。评测 LIBERO-X、EBench 和真机轮式双臂（煎蛋糕、刨土豆）。

这是又一个「对齐轴不在关节 / 末端二选一」的提案——简单动作段拉长、精细段缩短，对不同控制频率的本体混训是比重采样更自然的处理。但它没给出和 per-embodiment 训练的代价对比，这条线最想要的数字仍然没有。

## 6. 双臂 VLA 不会按臂分解：未见过的左右组合只有 3%

**Arm-wise Compositional Generalization in Dual-Arm Vision-Language-Action Models (ACG-Bench / AE-VLA)** · [arXiv](https://arxiv.org/abs/2610.06184)

大连理工（卢湖川、王立君组）。先立评测：23 个任务-条件对、8 个任务族、17 个训练时没见过的左右臂组合。然后数字很难看：单一 π0.5 在未见组合上 2.94%，MA-VLA 3.06%，左右各一个策略 5.53%——现有双臂 VLA 本质上记住的是整体动作，不是「左臂做 A + 右臂做 B」这种可拆的结构。AE-VLA 做三件事：把动作 token 按臂分组、每臂一个 SkillLoRA、臂间注意力，仿真到 21.53%，真机 SO101 从 10% 到 39%。消融里每个单项只有小幅提升，三个加在一起才跳上去。局限写得老实：双臂同步任务和域内任务没明显收益，而且假设已经给出了每臂的原子指令。

值得做的改动是评测层面的：双臂 benchmark 应该把「未见组合」单独拆成一栏，不然域内分数会把这个 3% 的洞盖住。

## 7. 长程记忆该存什么：条件化的变化量，不是状态本身

**EvoMem-VLA: State-Evolution Memory for Long-Horizon Robot Manipulation** · [arXiv](https://arxiv.org/abs/2610.05418)

西安交大 / 港科广 / 港中文 / Xbotics。记忆不存帧，存**有序帧对之间的条件化差分 token**，再按子任务做自适应路由。RMBench 80.7、RoboMME 82.0，真机 4 个任务 2 个本体 83.8。消融比主结果有用：去掉差分 token 掉 28.4 个点，去掉子任务路由掉 19.4，**朴素的特征相减（47.1）比完全不加记忆（44.3）只好一点、比条件化差分差 30 多个点。** 也就是说「记忆该存什么」的答案是变化量而不是状态，而且变化量要条件化才有用。它没做的是「记不住」占失败率多少的归因。

## 8. 一个归因陷阱：「加了几何模块涨 10.9 点」里几何只值 1 点

**GeoBridge-VLA: Geometry-Aware Residual Adaptation for Vision-Language-Action Models** · [arXiv](https://arxiv.org/abs/2610.05026)

嘉泉大学。选它是作为反面教材。主结果 LIBERO 70.9 对 SmolVLA 60.0，看起来几何先验有 10.9 个点的贡献。但同一 checkpoint 把几何残差置零后是 69.85——**残差本身只值 1.05 个点**（Spatial +3.2、Long +2.8、Object −1.2、Goal −0.6），剩下近 10 个点来自两阶段训练配方和解冻的 action projection。作者在文中承认实验「没有隔离几何的贡献」，但没有补一个同配方无几何的对照。真机 OMY 148/200 对 108/200 同样没有这个对照。

这篇改变的是读「加了 X 模块涨 N 点」这类结论的方式：一律要问有没有同配方去掉 X 的对照；只有推理时置零的数字时，涨幅里属于 X 的那部分往往只有零头，其余要归到配方。

## 9. 手套 + 接触 + 力：遮挡下手-物追踪失败帧从一半降到 2.5%

**VICON: Visual-Inertial-Contact based Hand-Object Tracking for Manipulation** · [arXiv](https://arxiv.org/abs/2610.05180)

DGIST / 首尔大。手套上的 IMU + RGB-D + 按抓握频率布点的 FSR（给接触和标定过的法向力），物体位姿不需要 CAD（单目视频重建 mesh），因子图融合。遮挡下的失败帧比例 2.5%，对比的纯视觉方法 50.9–64.6%；中位误差 3.9 mm / 3.0°。数据集说要扩到 10 个物体类别。对做第一人称操作数据采集的人来说，多出来的是接触与力的通道以及 FSR 布点的依据；遮挡期间的失败帧比例是这条线上该追的指标。

## 10. 不训练的速率控制，以及本期四篇对「块内重要性不均」的不同回答

**FreeSpeed: Training-Free Speed Control for Generative Robot Policies** · [arXiv](https://arxiv.org/abs/2610.05734)

南洋理工 MARS Lab + 珞石。不训练，只对预测出来的动作块重采样：用相邻动作的方向不一致度当「这一段是否关键」的信号，关键段放慢、非关键段加速。3 个策略族 50 个仿真任务做到 0.22–2.53 倍的速率范围，真机 94.0% 对原始 93.8%，速率 0.38–1.97 倍。

把它和第 2 条 RACE、以及同期的 DiVeR（[arXiv](https://arxiv.org/abs/2610.04933)，用采样动作的离散度定义关键步、做 verifier 引导的推理时扩展）放在一起看：三篇独立工作都把「动作块内各步重要性不均」当前提，而识别关键步用的信号各不相同——子技能切换位置、方向不一致度、采样离散度。再加上第 3 条对观测过期的刻画，本期四条都在块长、延迟与可靠性这个三角里做文章。这个三角的解空间显然还没收敛，但「块内均匀对待每一步」这个默认已经被多方放弃了。
