## 主线一：成功，和安全，是两件必须分开测的事

本期最有分量的两条工作指向同一件事：**目前几乎所有操作策略的评测，都把「安全」当成「成功」的副产品在测，而这个假设是错的。**

### 成功的 rollout 里，有 6 到 21% 在违规

[ManiGuard: A Benchmark and Data Suite for Specification-Grounded Safety Evaluation and Improvement of Robotic Manipulation](https://arxiv.org/abs/2608.17386)

它的设计里有一个关键决定：**安全规格独立于任务成功来定义**。六类接触密集的家务任务、200 个锁定的基础任务，按「技能 × 约束」两个轴组织；每个任务在 1 个分布内加 4 个单轴分布外扰动下评测，扰动过程中安全规格保持不变，一共 1000 个锁定场景。

判定方式也值得单说。它不用学出来的分类器，也不用大模型当裁判，而是用 LTL_f 自动机监控器在**物理谓词**上做逐步的运行时检查，仿真和真机 Franka 上都跑。这一条很重要——用大模型判安全，等于用一个没有校准过的东西去校准另一个。

23000 多次 rollout 之后的三层结论，一层比一层难听：

1. **成功的 rollout 里有 6-21% 违反了安全规格。** 也就是说，成功率这个指标系统性地掩盖了两成左右的危险行为。
2. 在这套带安全标注的数据（8000 条演示，每个基础任务 40 条，已放出）上微调确实有用：「安全完成」从接近零抬到 7.5-29.8%，「参与且安全」从 16-40% 抬到 51-72%。
3. **但缺口不是加数据能补上的。** 21-42% 的参与 rollout 仍在违规；六类任务里有两类，对所有被测策略都低于 2% 的安全成功率；而且这些失败在分布漂移下和真机硬件上都持续存在。

第三点是这篇真正的贡献。它把「安全靠 scaling 解决」这条默认路径实测着堵死了一段——**至少在这个规格框架下，演示数量与安全性之间存在一个不随数据量关闭的缺口**。这意味着安全不能只作为数据问题处理，得在策略结构或运行时监控层面另找出路。

### 视觉线索是一条没人授权的控制通道

[LIBERO-VIFO: Benchmarking the Capability and Safety of Visual Cue Following in Vision-Language-Action Models](https://arxiv.org/abs/2608.17600)

在场景里画箭头、标记点来引导机器人，是个越来越常见的做法。但一个几乎没人系统问过的问题是：视觉-语言-动作模型能不能可靠地跟随**被授权的**线索，同时**忽略未授权的**线索？已有工作只覆盖很窄的线索形式，而且只看最终任务成功率——这等于默认所有出现在画面里的视觉线索都是合法指令。

LIBERO-VIFO 定义了八个视觉线索族、两部分共四套协议。第一部分测线索理解与授权跟随；第二部分才是要害，它在「语言与线索冲突」和「空语言」两种条件下测未授权跟随。七个 VLA 模型评下来，两个发现：

- **线索的理解并不可靠地转化为执行**——模型说得对，做不对。
- **当前 VLA 在完全没有语言指令时，也会执行线索所指示的任务。**

后面这条的含义值得停一下：它意味着画面里的视觉标记构成了一条**事实上的控制通道**，而这条通道从未被纳入任何权限模型。场景实例化线索、安全关键设定、真机部署上的扩展实验都印证了这一点。把它和 ManiGuard 放在一起看，两篇是同一个问题的两面——一个说成功掩盖了不安全，一个说输入通道比设计者以为的要宽。

## 主线二：跨本体的对齐轴，正在从动作空间挪到观测空间

「不同机器人的动作空间怎么统一」长期以来是个二选一的问题：对齐到关节空间，还是对齐到末端位姿。本期两条工作都没有在这道题上选边，而是把对齐这件事整个挪到了观测侧。

### 把动作表示成像素运动

[Hydra-0: Action Flow for Generalist World Modeling and Control](https://arxiv.org/abs/2608.18077)

Hydra-0 用 **action flow ——即像素运动——来表示机器人动作**，把它当作一个共享的视觉接口，同时支撑世界建模和控制，并跨本体、跨任务、跨环境、跨视频生成 backbone 复用。相对 action-conditioned 的基线，最好的配置把机器人运动误差降了 90.4%、物体运动误差降了 60.2%，同时支持零样本组合与数据高效适配。

这是本期最能改变做法的一条。**如果动作可以在像素空间对齐，那么「统一动作表示」就不必是一个动作空间问题。** 观测侧的共享接口有一个动作空间对齐永远给不了的性质：人类视频和异构机器人数据可以喂进同一个接口，因为像素运动对两者都有定义，而关节角只对特定本体有定义。

另外两个结果同样值得注意。一是在 RoboLab 基准上，重放成功率与参考成功率的 Pearson 相关达到 **r=0.96**——这个数字意味着这个世界模型可以当**开环的策略评测器**用，而不只是一个生成器。二是一个涌现出来的逆向模式：把人类演示中的期望 object flow 迁移过来，模型可以反推出兼容的机器人运动，再由一个训练好的动作头映射成可执行动作，**全程不需要任务特定的机器人专家演示**。

### 让本体构型决定看多少辅助视图

[EATR-Stereo: Embodiment-Aware Routing of Paired Stereo Evidence for Humanoid Vision-Language-Action Control](https://arxiv.org/abs/2608.17453)

同一个思路的另一个版本，锚在头戴双目相机的人形机器人上。已有的视觉接口处理双目的方式有两种毛病：要么直接丢掉互补的另一路证据，要么在融合额外观测时破坏了预训练模型的原生主视图通路，而且没有把辅助信息适配到具体机器人本体。

EATR-Stereo 保留主视图 token 不动，通过查询同步的辅助视图 token 序列，构造出**与主视图对齐的跨视图辅助 token**；再用一个按身体分段的本体感受编码器，让每个 token 用多少辅助信息，以机器人的构型历史为条件——这就是标题里「embodiment-aware」的实指。路由出来的辅助流去增广预训练 VLA 的语言与主视觉上下文，而**视觉语言模型本身保持冻结**。

33 自由度真机人形（37 维本体感受状态）上，超过 100 秒的「搜索-接近-抓取-放置-返回」长程任务评了九种配置：全任务成功率 60.0%、抓取成功率 100.0%、阶段成功率 80.0%。最说明问题的是消融：严重非对称遮挡下，恢复率从只用跨视图辅助 token 的 30% 提到 80%——**说明起作用的不是「多了一路视图」，而是「按本体构型决定何时用它」**。

## 主线三：不重训主干，也能改行为

三条工作走的是同一条路子：预训练策略冻着不动，在外面挂一层。这条路子的吸引力很直接——重训一次的代价太高。

[Teach and Grow: An Agent-Centered Architecture for General Robot Learning](https://arxiv.org/abs/2608.17209) 给这个代价起了个名字：**retraining tax（重训税）**。端到端 VLA 与世界-动作模型的可靠性，被「已验证的物理覆盖范围」卡着；一旦遇到覆盖外的物体、传感器、本体或接触形式，而又没有已验证的兜底，修复一次失败就要走一遍新数据采集、策略更新、回归测试。而与文本不同，具身数据往往得靠操作真机才能造出来。

TGL 的做法是让一个多模态 agent 把少量成功演示变成可复用的 **Skill Block**（针对有意义子目标的闭环行为）。新场景里，agent 负责把这些块 grounding 并组合起来、在学出来的工具和几何工具之间做选择、观察物理结果、在执行偏离意图时改路线。Skill Library 存可执行行为，结构化的 Experience Memory 把成功、失败和修复带到后面的任务里。新任务的获取**不需要任务特定的策略重训**。LIBERO 上达到 SOTA，受控实验分别验证了技能归纳、持续复用和 agent 主导的适配。作者还提了一个 scaling-law 猜想：以 X 记有效可复用经验，未来任务的误差与教学需求应当按 X 的幂律趋近于各自的不可约下界。

[UniReflex: Plug-and-Play Force Control for Pretrained Generative Policies via Fast-Slow Reflex](https://arxiv.org/abs/2608.17432) 处理的是另一个具体缺口：生成式模仿学习策略擅长轨迹规划，但没有闭环力调节；而直接把力模态塞进网络通常意味着重新设计或重训。UniReflex 不碰慢主干，**非侵入式地从 action head 截取深层 latent 表示**，用它驱动一个快反射网络，把主动施力和外部交互响应解耦，预测归一化的各向异性刚度方向来做方向性柔顺分配；再加一个自适应门控，在位置主导的规划与力主导的执行之间平滑切换。力方向意图是在演示采集阶段顺带收的。真机双臂实验里接触稳定性和成功率都提升，同时保住了原有的位置精度；相对联合训练策略，**每步反向延迟低 25-66 倍**。

[ORPA: Online Residual Policy Adaptation for Robot Manipulation Control with Human Feedback](https://arxiv.org/abs/2608.17323) 是这条路子最朴素的一版。ACT 这类模仿学习策略在理想条件下表现不错，但对小的执行误差和分布漂移敏感；修这些失败通常要 DAgger 式的数据聚合加全策略重训，在实时部署里不现实。ORPA 给预训练策略挂一个轻量的、以反馈为条件的模块，**直接在关节空间预测残差修正**，完全不改动底层策略参数。ALOHA 平台上一组精度敏感任务里，成功率和从小扰动中恢复的能力都优于基线策略以及基于规则的逆运动学修正。

值得注意的是这三条的共同结构：**冻结主干规避的不只是算力，还有灾难性遗忘**——参数不动，旧能力就不会掉。代价则统一落在推理时的额外开销上。

## 另外两条

[Prism-GRPO: Faster VLA Policy Optimization via Splitting Same-outcome Groups](https://arxiv.org/abs/2608.17423) 修的是 GRPO 训 VLA 时一个具体的浪费。GRPO 相对 PPO 的好处是不用训 critic，代价是每个场景需要多条 rollout 才能算组内相对优势。在二值成功奖励下，全部成功或全部失败的组优势为零，会被动态采样直接丢弃——而**训练早期恰恰是大部分 rollout 都失败的时候**，昂贵的机器人 rollout 预算就这么烧掉了。

Prism-GRPO 在二值结果奖励之上叠加一个加权的**轨迹级执行质量分**，把同结果的组摊开成一个质量谱，既回收了训练信号，又保证任何一次成功仍然排在任何一次失败之前。质量分可以从仿真器接触、已执行动作或视觉观测里导出，**不需要为每个任务手工设计 progress reward**——这是它比「加个塑形奖励」高明的地方。论文还证明了它不会增加「某个组因零优势被丢弃」的概率，并给出了组合更新仍是任务成功的局部上升方向的梯度对齐条件。四个 RoboTwin 任务（覆盖不同时长与协同模式）上，同等 rollout 预算下成功率与质量都提升，达到目标成功率所需的 rollout 最多减少 56%。

[Q-Learning With World Models (QWM)](https://arxiv.org/abs/2608.17163) 换了个位置放世界模型。已有的 model-based 强化学习大多直接在想象出来的 rollout 上优化策略或价值函数，容易累积模型偏差，任务时长和视觉复杂度一上升就更糟。QWM 让策略和价值函数**只在真实 transition 上训练**，世界模型仅用于在线 rollout 和评测时对想象轨迹做**推理时搜索**，挑出高价值动作。这样既拿到预测式搜索带来的样本效率，又避开了复合模型偏差。Robomimic 和 LIBERO 上，样本效率与最终性能都显著超过此前的强基线。

最后一条不是具身工作，但对着一个具身侧长期没有答案的问题：[Harness the Memory: A Holistic Evaluation of Memory Substrates in Memory Agents](https://arxiv.org/abs/2608.15008)。它在统一的 harness 下受控评测了各类记忆**基质**——稠密与稀疏索引、文本记录、结构化存储、层级存储、精炼式记忆、参数化更新、以及激活兼容的上下文机制；三个 backbone、四个 benchmark 套件、26 项性能与效率指标。

结论是没有单一基质全面占优，其中一条对做长程操作的人尤其值得记：**宽召回有利于长上下文事实问答，但过度召回会损害序列决策，因为它把注意力从动作关键的上下文上挪开了。** 换句话说，「记得多」和「做得对」在决策任务上是有冲突的。可扩展性还引入了另一根轴：在中等历史长度下表现良好的基质，到更长时长会变得昂贵或脆弱。作者据此主张，**基质路由本身**应当是自适应记忆系统的一个必要组件，而不是选型阶段一次性拍板的事。

## 检索层的说明

本期主动检索的三个问题里，第三个（跨本体动作表示统一到什么程度）命中一条：**MOTIF: Learning Action Motifs for Few-shot Cross-Embodiment Transfer**（[arXiv 2602.13764](https://arxiv.org/abs/2602.13764)，2026 年 2 月）。它明确把现有 shared-private 架构的两个缺陷摆上台面——私有参数容量有限、缺乏显式的适配机制——并提出用 action motif 把「与本体无关的技能结构」和「与本体相关的执行细节」解耦，来做少样本跨本体迁移。

但三次尝试都只拿到了截断的摘要，方法细节与量化结果（成功率、所需演示条数、对比基线）一概没有拿到。**所以这里只报告它的存在和主张，不写摘要**——靠半截摘要写方法必然会编出不存在的东西。留待下一轮专门去读。
