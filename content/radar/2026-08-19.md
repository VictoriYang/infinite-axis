## 主线：记忆和适应，正在从权重和上下文里搬出去

如果把本期几条最好的工作摆在一起看，会发现它们在回答同一个问题的不同版本：**一个策略需要「记住」和「适应」，这两样东西该装在哪里？**

默认答案一直是两个：装进上下文（把更长的历史喂进去），或者装进权重（微调、在线更新、测试时训练）。本期四条工作，四个都不是这两个答案。

### 1. 记忆装进一个可训练的关键帧检索器

[MemER: Scaling Up Memory for Robot Control via Experience Retrieval](https://arxiv.org/abs/2510.20328)（Ajay Sridhar、Jennifer Pan、Satvik Sharma、Chelsea Finn）

论证从否掉两个显然解开始：直接吃长观测历史，算力贵、而且在协变量偏移下脆弱；对历史做无差别降采样，又会引入大量无关和冗余信息。这两个失败模式其实是一件事的两面——**问题不在于历史有多长，而在于没人决定该看哪几帧。**

于是他们把「决定看哪几帧」本身变成一个被训练的对象：分层策略，高层策略学着从自己的经验里挑选并跟踪相关的关键帧，把选中的关键帧连同最近若干帧一起用来生成文字指令，交给低层策略执行。实现上高层是微调过的 Qwen2.5-VL-7B-Instruct，低层直接用 π₀.₅，训练数据是补了极少量语言标注的示教。在三个需要**分钟级**记忆的真机长程操作任务上超过已有方法。

值得单独指出的是：低层一行没改。这意味着这套东西是挂在现成 VLA 上的，不是一个新架构。

把这条和「上下文窗口不够长」的叙事放在一起看，结论是有分量的：长程记忆不必然是一个规模问题，它可以是一个检索问题——而检索的选择器是可以学的。

### 2. 空间状态搬到模型外面，还带一路可信度信号

[Alaya-EVOKE](https://mp.weixin.qq.com/s?__biz=MzIzNjc1NzUzMw==&mid=2247913001&idx=3&sn=0ffd266a88f762bb4366ada6614a51e5)（Alaya Lab、中科大、上海创智学院）

视频世界模型的老问题：跑久了画面发灰过曝、场景悄悄换地方、显存撑不住。EVOKE 把连续生成拉到 120 分钟、4800 个片段、172800 帧，亮度饱和度对比度一路稳住，而且上下文有固定上界、单步成本不随会话变长。

做法的第一半是**把空间状态挪到模型外面**。学生模型只留最近 19 个 latent 帧（约 3.2 秒），走出这个窗口的内容不再进上下文，而是写进一个**以相机位姿为地址**的外部「世界状态银行」：单目深度把新片段反投影成持久点云，各片段几何独立插入以避开长序列深度融合的尺度漂移；读取时当前位姿就是地址，候选源视角按共视度排序、最多取 8 个做批量 z-buffer 投影，返回对齐当前视角的 warp 图和逐像素可见性掩码。整套读写逐出都在 CPU 内存侧，不占显存。

真正有意思的是掩码那一步：**它同时决定这段记忆能被信任到什么程度。** 可见性低于 0.5 的像素直接赋 σ=1，等于明确告诉模型「这里什么都没给你」；有几何支撑的地方才只加很轻的噪声。这是个容易被跳过但很重要的设计——**外部记忆如果不带覆盖度信号，不可靠的记忆比没有记忆更糟**，因为模型分不清「记忆说这里是空的」和「记忆没覆盖这里」。

第二半是重做教师模型。多数工作里蒸馏只是加速手段，教师本身没为长时序监督设计过：双向注意力开销随序列长度平方增长，训练只能限在短片段，而且整段共享一个提示词。EVOKE 把 Wan2.2 A14B 改成线性注意力加分块（首帧 sink + 本地片段 + 压缩近邻帧 + 按重要性挑的远帧），注意力从二次降到近似线性，于是能给 30 秒级的长时程监督，还支持中途换 prompt。这一改的必要性有对照支持：**只换教师、其他全同**的两个三步学生里，短时程教师带出的那个亮度掉到开场的 74%，长时程教师带出的停在 101%，8 段里 7 段改善。理由很直白——色彩漂移和内容漂移这类退化只在时间跨度足够长之后才暴露，短窗口监督根本看不见它。

工程数字：三步去噪、零 CFG，单卡 H200 生成 1.5 秒 384×640 视频，扩散部分 2.11 秒。弱项也写明了：导航与视角分数偏低；中途换指令若指向尚未锚定的区域（比如天空）有 67% 兑现，若要覆盖已经被世界状态渲染过的几何就只剩 4%——外部记忆强到会压过用户指令，作者的建议是切换时对几何参考做 mask。

### 3. 适应装进采样过程，一个参数都不改

[VLS: Steering Pretrained Robot Policies via Vision-Language Models](https://arxiv.org/abs/2602.03973)

这篇开头问的问题很具体：同一个任务，只要挪到障碍物旁边、换个支撑面高度、或者场景稍微乱一点，预训练的 diffusion / flow-matching 策略为什么就崩了？

答案是本期最值得记的一句判断：**这类失败很少反映「缺少运动技能」。** 它暴露的是模仿学习在训练-测试偏移下的局限——动作生成和训练时的特定空间构型、特定任务描述耦合得太死。需要的行为本来就在模型里，只是没办法在测试时被选择性地调出来。作者由此推出一个方法论上的结论：为了这类失败去重训或微调，既贵，而且**概念上不对路**。

VLS 因此完全不训练：冻结策略，用视觉-语言模型合成对轨迹可微的奖励函数，拿它引导去噪采样，朝满足测试时空间与任务要求的轨迹走。CALVIN 上比已有 steering 方法高 31%，LIBERO-PRO 高 13%，真机 Franka 上在空间与语义偏移下同样成立。

把它放到「推理时学习」这条线上看，它提供的是一个和测试时训练（改快权重）完全不同的容器：**同样是部署后变强，但落点在采样过程而不是参数。** 更实际的影响是给这条线设了一个更严的对照——一个主张「必须在部署时更新权重」的方法，现在需要先证明免训练的采样引导做不到同样的事。

### 4. 跨本体的「统一」，也可以不放在动作空间上

[CurrentWorld-0](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651050789&idx=2&sn=ad80098f33a57c6e63e5ea2fd0971bda)（Current Robotics）

这是 Current Robotics 在人形全身精细操作 Curr-0 之后的第二份工作，定位是交互式世界仿真器：不靠人工编写物理公式，而是从真实交互数据里学「机器人做出一个动作之后，世界接下来会怎样」。同方向已经有 1X 的 1X World Model、Physical Intelligence 的 Ctrl-World 与 SC3-Eval、DeepMind 的 WorldGym、NVIDIA 的 Cosmos Predict；它自称的增量是首次把**跨本体、多视角、力-触预测**放进同一个仿真器。

它想解决的是评测的规模问题。训练语言模型可以同时跑成千上万个 benchmark case，但到了机器人这里，机器人数量、场地、人工看护和任务复位都限制着测试规模。传统物理仿真解决了一部分，前提是「你得先知道这个世界该怎么被建模」——刚体、摩擦、关节可以人工定义，但叠袜子、抹面包、倒啤酒背后的柔性物体、流体和复杂接触很难一条条写进物理引擎。所以问题变成：能不能把真实世界本身「学」进一个可以无限运行的环境里。

**跨本体那一段是这条工作里最值得抄走的判断。** 固定双臂、移动双臂和人形机器人的自由度、运动学结构和控制方式都不相同，而 CurrentWorld 的选择是**不强行让它们共享一套动作空间，而是为不同机器人各自保留一个 Action Subspace**；共享的是它们作用于世界时遵循的同一套物理规律。原文那句话概括得很好：不同的是身体，相同的是它们作用于世界时遵循的物理规律。

这值得和「跨本体动作表示能统一到什么程度」这个开放问题对着看。近两年的主流路线——per-embodiment projector、动作 tokenizer——都在赌不同机器人的动作空间可以对齐，而这个赌注被验证到什么程度一直是开放的。CurrentWorld 给的是另一个选项：**把统一放到世界这一侧**，动作空间反而明确保留异质。换句话说，「对齐轴选在哪一层」这个决定，可能比「对齐做得多好」更值得先想清楚。

还有一个前提条件值得单独记：这套东西能不能当考场，取决于**动作是否真正算数**。视频模型有很强的视觉与运动先验，但这对评测未必是好事——机械臂已经抓偏了，模型可能沿着更熟悉的轨迹继续生成，让物体「自动」跟着夹爪走，任务实际失败而画面补出一个成功结局。一旦世界模型开始替机器人纠错，评测就失去意义。团队此前的 dWorldEval（ICML 2026 Spotlight）研究的正是这种动作可控性：动作没做对，世界也必须允许失败真实发生。

需要说明：这一篇的正文我只读到多视角那一节，**力-触觉的具体做法和任何定量结果都没读到**，所以上面没有任何数字。

## 反面：记忆不是白拿的

上面四条容易读成「把东西挪出去就对了」，所以本期另一条工作放在这里当配重。

[PACE-Bench: Benchmarking Physics Adaptation via Code Evolution in Dynamic Environments](https://huggingface.co/papers/2608.14441)（清华 THUNLP）

针对的是自进化 agent 评测里一个真实的漏洞：现有评测通常在**固定的执行条件**下优化，从不测「条件变了之后能不能恢复」。PACE-Bench 造了 144 对 source→target 适应任务，横跨六个物理域。每一对里，源环境中跑得通的代码化方案，在目标环境（同样的目标、同样的接口，但物理被改动过）会失败；agent 必须在有限尝试预算内，靠沙箱的诊断反馈把它迭代改对。十种自进化方法、四类范式一起比。

远未饱和：Reflexion + Qwen3-14B 在全集只成功 35.9%；GPT-5.5 在 Statics 子集、给足预算的情况下 66.7%。四条结论都值得单独记：

- **有仿真器验证的反思，比无验证的自我修改可靠得多。**
- **记忆会把 agent 锚死在早期设计上。** 这条是反直觉的——在这个任务里记忆是负作用，因为要适应就得放弃原方案，而记忆一直把它拉回去。
- 宽的树搜索只探索，不收敛。
- **把确切的物理变化直接告诉 agent，天花板也不涨。**

最后那条最重要。它把瓶颈从「发现环境变了什么」挪到了「重新设计机制」。如果直觉是「只要把变化识别准，方案自然能改对」，这个实验就是直接的反证：答案免费给你，成绩不动。**参数推断不是瓶颈，机制重设计才是。**

配合第一条结论，对任何想搭失败-恢复自生成闭环的人，可操作的结论很清楚：标注「哪里变了」的价值有限，能把改动跑一遍并给出诊断的可验证沙箱才是关键部件。而配合第二条，技能库这类持续追加的结构需要一条主动废弃旧机制的路径，不能只做追加。

## 评测那一侧：分数之外要留下证据

两条方法论工作，主题不同但形状一样：都在说「一个分数不够，要能查」。

**[HarnessEval-W: Agentifying the Evaluation of Visual Worlds](https://huggingface.co/papers/2608.16859)** 的出发点是一句好话：一个 benchmark 该给的不只是一个标量分数，**让评测可信的是证明这个分数的推理过程**。对世界模型尤其如此——判断一段 rollout 好不好，本质是判断物理、因果和世界状态有没有正确演化；人能一眼看出违反，但现有指标都是暴力算出来的，留不下任何可以检查、可以验证的推理链。做法是把大模型生态里的 harness 范式搬过来：不套固定 rubric，而是解读每个评测 case 的上下文，把评测问题分解成可测量的子问题，为每个子问题派一个带专属上下文和诊断工具的子 agent 去推理，父 agent 校验收集到的证据再汇总成最终判断——整个过程留下一棵完整的证据树。在 18 个代表性世界模型、330 个 case 上，判断与人类偏好接近，同时给出细粒度诊断。全流水线开源为可持续生长的 live benchmark。

它和 CurrentWorld-0 是一组：想让世界模型当机器人的考场，得先有东西能考世界模型本身。

**[How Do Agents Fail on AutoResearch](https://huggingface.co/papers/2608.14905)** 的主题（科研 agent）离机器人很远，收它是因为方法可搬。100 个基于已发表前沿科学的任务、7 个学科，覆盖 ideation / retrieval / execution / analysis / writing / review 全流程；8 个 harness-模型组合跑出 800 条轨迹，做**过程级标注**，归纳成 45 个有实证支撑的失败模式，再用人工校准过的 agent-as-a-judge 流水线去检查完整轨迹和中间产物。结论是所有失败模式收敛到同一件事：**缺乏元认知回路**——把自己产出的东西对照自己查到的东西、对不上时修改、并质疑走过的路本身是否成立。

有两点值得学。一是「过程级标注 + 检查中间产物」这个评测形态：具身评测目前绝大多数只报一个成功率，而成功率对「为什么失败」不提供任何信息。二是它定位缺陷层级的方式——同一批失败模式在全部 8 个 harness-模型组合里复现，包括测过的最强模型，作者据此把缺陷定位在**模型层而非某个 scaffold**；而且明说了编排层的干预能不能补上，本文没测。这种「跨组合复现同一模式 ⇒ 缺陷在模型层」加上「没测的部分明确说没测」的论证结构，值得直接借用。

## 另外两条

**[Direct Perception Control](https://mp.weixin.qq.com/s?__biz=MzA3MzI4MjgzMw==&mid=2651050789&idx=1&sn=24d0089b094af36e6e81d18a30d3ba89)（Symbiosis Robotics）。** 演示是人形机器人压低身体钻进卡丁车座舱、上赛道驾驶（双手控方向、右脚油门、左脚刹车）。技术主张是取消需要独立 Whole-Body Tracker 追踪的中间运动表示，让模型直接读画面、任务语言和身体反馈，输出关节与手部目标；训练用了 15,010 小时具身数据。

演示本身不重要，文章对分层方案（Figure Helix、Gemini Robotics 2，以及 ω-0、MotionWAM、Ψ₀）三处代价的拆解更有价值：其一，latent 里相近的运动意图，经过身体状态的条件映射后可能对应差异明显的关节动作，「怎么发力、怎么维持支撑」这些关键选择发生在运动接口**之后**，上层再懂任务也拿不到；其二，上层策略和底层 tracker 分开训练、直到部署才通过接口接上，底层动作产生的误差和随之而来的画面变化没法回来调上层；其三，底层控制器被冻结，就等于机器人的动作范围被它的训练数据封顶，而底层先验主要学的是行走，钻进狭窄座舱要在小空间里重排全身姿态、驾驶要求上下肢持续配合，这些恰好落在行走数据覆盖之外。

这三条可以直接拿去审任何分层设计。但必须说明：**这篇没有给出任何定量对比或消融**，目前只能当一次方向性表态，不能当已验证的结论用。

**[KnowAct-GUIClaw](https://arxiv.org/abs/2607.12625)（哈工大）。** 表面是 GUI agent（在长程 GUI 基准 MobileWorld 上 SOTA），但三个机制是跨领域的，对任何想做技能自主入库的人都有用。一是跨应用的中间结果走**带类型的黑板**而不是一段不断增长的自由文本摘要：每个子任务显式声明目标应用、所需输入、应返回的输出，必需输入或声明输出缺失时工作流**直接停**，而不是让下游猜或编。二是技能不是旧轨迹的机械重放——每个技能带适用平台、参数、**可靠性统计**和**状态契约**，调用前检索候选、执行中逐步检查当前状态是否满足预期，不满足则有限恢复、跳过可选步骤，或退回到最原始的操作方式。三是快捷路径一律「先发现、后验证」：清单能证明某个入口可能存在，但不能证明它在真实设备上可用、更不能证明它落到正确的地方，所以要实际启动候选入口去验证。

对比「存一条成功轨迹然后重放」的朴素技能库，可靠性统计加状态契约这套要扎实得多。

**[PhyEdit](https://arxiv.org/abs/2604.07230)（浙大 ReLER，ACM MM 2026）** 收在这里主要是因为它自己划的那条界。方法上是：冻结的 3D 基础模型（默认 Depth-Anything-3）估深度和相机参数，把选中像素反投影成点云、在三维空间按给定位移移动、再投影成一张粗糙预览图；这张预览图消除语言里的空间歧义（新位置、投影尺度、前后遮挡顺序），原图继续提供纹理与环境，DiT 图像编辑器负责融合渲染，训练额外加像素级 SILog 深度损失防止「外观像了但深度还是错的」。ManipEval 上 DIoU 65.33、Chamfer 18.93，盲测整体偏好 78.0%；同时完成三维移动和附加外观编辑的综合成功率 87.5%，只比基础模型单跑纯编辑的 88.8% 低 1.3 个点，而三维 Chamfer 20.97 远低于后者的 46.31。换掉几何估计器（DA2 / MoGe / VGGT / Pi3X / DA3）都保持正的平均几何增益，说明收益不绑定某一个深度模型。数据集与权重都放了。

而那条界是：**它不是一个自主预测动作的 dynamics model，轨迹仍然由用户给定，它做的是把给定的三维动作渲染成可信的视觉状态。** 在世界模型这个词被用得越来越宽的时候，「渲染给定动作」和「预测动作的后果」是两件事，把它们混起来会高估自己手里有什么。作者自己把这句写在正文里，比那些指标更值得记。
