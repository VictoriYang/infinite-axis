## 一、世界模型接进 VLA 的收益，平均值是骗人的

### Utility-WAM: Correcting Future-Induced Action Changes

[arXiv:2610.39367](https://arxiv.org/abs/2610.39367)

「让策略先想象一下未来的画面，再决定动作」是过去一年里 world-action 模型最流行的设计。这篇论文做了一件此前没人单独做的事：把这个设计**到底改变了什么**量化出来——同一个模型 checkpoint 下，future-conditioned 与 future-free 两条执行路径之间的动作差 Δa。

结果是：对平均成功率的影响在 LIBERO 上是 **+0.8 分**，在 RoboTwin 2.0 上是 **−0.8 分**，而生成视觉未来让推理延迟涨了 **1.7 到 1.9 倍**。

但真正的发现是平均数掩盖了什么。作者称之为 **future-induced negative transfer**：长程任务确实受益（LIBERO-Long +2.4），绝大多数常规操作可忽略不计，而**精密任务定向崩坏**——Press Stapler 掉 54.0 分，Place Can Basket 掉 34.0 分。关键细节是，这两个任务在多个**独立训练**的 world-action 模型变体里都反复出现在失败榜首，说明这不是某次训练的偶然。

解法有两件。一个残差 adapter 在冻结主模型上就地修正 future 引起的速度偏差，把上述两个任务的损失压到 6.0 和 14.0，同时保留长程任务的收益。更有意思的是第二件：一个轻量的预生成门，复用反事实动作结果来判断这一帧要不要生成视频，在 RoboTwin 上**直接跳过了 75.5% 的视频生成**，延迟降 38%，而平均成功率反而升到 93.3%（LIBERO 98.9%）。真机双臂三个任务 53/60，对照 FAST-WAM 的 43/60。

**这改变了什么**：此前对「VLA 要不要接世界模型」的讨论框架是「有用但贵」的权衡，该问的是值不值得那一倍多的延迟。这篇之后该换个问法——平均意义上它几乎不值，而且在精密任务上是定向有害的。更重要的是做法层面：future-conditioning 不应该当成全局架构开关来调，而是一个**逐 query 的判别问题**。三分之二以上的 query 根本不需要想象未来，而「这一帧需不需要」本身是可以学的。这同时解释了一类容易被归因错的现象：接了世界模型之后「平均没涨但个别任务崩了」，很容易被当成训练不充分，它其实是机制性的。

### 一条值得对照的旁证

同期有一篇攻击向的工作 [PASA-KV](https://arxiv.org/abs/2610.39816)，结论与上面形成有意思的呼应：world-action 模型内部**表示的可扰动性与闭环脆弱性之间存在明显错配**——更大的表示位移并不可靠地意味着更强的控制失败，因为效果取决于扰动如何被**路由进动作生成**（K 决定动作查询读哪里，V 决定读到什么内容）。

把这两篇放在一起，共同的意思是：world-action 模型内部那条「世界表示 → 动作」的通路，其行为后果无法从表示空间的度量推出来。对任何想用表示相似度当代理指标的做法，这是个警告。

## 二、跨本体对齐：轴可能一直选错了

今天有三篇工作从不同方向指向同一件事——跨本体迁移里，大家默认的对齐轴（机器人本体、运动学）可能不是真正的冲突所在。

### Cross-Controller Transfer via In-Context Behavior Adaptation

[arXiv:2610.39280](https://arxiv.org/abs/2610.39280) · [项目页](https://controller-transfer.github.io)

Jonathan Yang、Chelsea Finn、Dorsa Sadigh。它指出泛化策略的数据假设里藏着一条没人明说的前提：**每台机器人只有一个控制器**。一旦这条不成立，同一个动作指令在不同控制器下的物理含义就不同，完成同一任务所需的策略也不同。

实验跨 **6 种控制器类型**，外加 controller gain 与 compliance 的变化。相比 naive data pooling，他们的方法平均高 **33 个百分点**；未见过的控制器模式上 50%，未见过的 gain 上 52%。方法上也值得注意：不是再加一层 per-embodiment projector，而是把「下发动作 → 实际产生的运动」这组交互样例当作证据，用一个 transformer context encoder 压成上下文，让**单个策略在上下文里完成适配**。在 USB 插入、擦桌面这类接触密集任务上，策略不只调整动作，连策略本身都变了。

**这改变了什么**：主流做法把异构数据混训的冲突轴认定为「本体」——不同机器人动作空间不同，所以每个本体一个 projector、按机器人分组调配比。这篇把控制器从本体里拆出来之后，分组键应该是**（本体 × 控制器模式 × gain/compliance）**，而不只是本体。这对数据采集有一个很直接的推论：控制器配置必须作为一等元数据记录下来，否则事后根本无法按它分组——而现有的公开数据集基本没有这么做。另外，用上下文内适配而不是重训 projector，对已有 checkpoint 要便宜得多。

### 两组人同日把对齐轴从运动学换成了接触

[TouchBridge](https://arxiv.org/abs/2610.40349)（清华 Huazhe Xu 组）做人手到机器人的数据转换。核心 Tac-Retarget 用**实测的指尖接触**来对齐接触斑块、并保持手内与跨手的空间关系。它最值得注意的性质是减法：**不需要物体 mesh、不需要物体位姿估计、不需要物理仿真**。四个真实接触密集任务上，只用转换后的人手数据微调预训练 VLA 得到 **72.5%** 平均成功率，等量遥操数据是 **77.5%**，但人手采集**快 7.0 倍**。同策略同训练设置下，Tac-Retarget 比 DexPilot 高 25.0、比 UniDex 高 42.5 个百分点。

[Kinematic-Tactile Aligned Dexterous Retargeting](https://arxiv.org/abs/2610.39582)（上海交大 Shuo Jiang、Peter Shull 组）同一天、同方向、不同路子。它指出现有 retarget 方法只迁移运动学，**支撑物理交互的触觉信息在跨本体时基本丢失**，于是用**以物体为中心的接触力扭空间（contact wrench space）**当触觉对齐的物理表示：先对齐手部运动学与接触几何，再从触觉力构出人手的 wrench 支撑轮廓，然后优化机器人指尖力目标去覆盖这个轮廓并转成关节位置修正。三种倒水条件下真机重放成功率 **96.7%**。

**这改变了什么**：人手数据转机器人，此前的瓶颈认定是视觉与运动学 retarget 的精度，于是投入方向是更好的手部 pose 估计加带物体 mesh 的仿真重放。把对齐锚点换成实测接触之后，那整套重建管线不再必要，而质量差距只剩 5 个百分点、吞吐是 7 倍。两组人独立收敛到「接触而非运动学」这个判断，比任何单篇的数字都更有信息量。它也把采集硬件上的触觉传感从「nice-to-have」变成了 retarget 管线的**必要输入**。

顺带，[Tactus](https://arxiv.org/abs/2610.39076) 正好给出了这层硬件的量化基线。这是一只纺织一体化的触觉 + pose 手套（1.5 mm 指尖堆叠、按实测接触研究布点的电容传感、IMU 融合的遮挡鲁棒 pose 跟踪），但它更大的贡献是提出了**标准化的触觉力回归与手部 pose 评测协议**，并把自己和两款商用触觉手套放在一起测——据作者说是这类首次定量跨平台对比。数字：最小可测力 **0.59 N**（95% 置信），比商用基线低 **1.6–2.7 倍**；跨被试一致性 0.87；遮挡最重时指尖关键点相对误差 **11.0 mm**。此前这类手套的选型只能看厂商参数，现在有了可对账的协议。

## 三、评测：数字孪生可以用来选型，不能用来报数

### SO-101 Bench: Accessible Spatial Manipulation

[HuggingFace Papers](https://huggingface.co/papers/2610.36420)

SO-101 这类低成本臂现在是进入机器人学习最常见的入口，但论文指出一个尴尬事实：**没有任何已发布的策略能开箱做好这上面的空间约束、语言条件任务**，而现有的 SO-101 基准只跑在物理硬件上、任务简单、留出物体很少。于是作者在真实 SO-101 setup 的 Isaac Lab 数字孪生上建了一个基准：四个任务按五族计分，138 个物体分 seen / unseen-instance / unseen-class 三档，916 条评测 episode（含留出外观、旋转塞入式规划、遮挡记忆三个子集），3,629 条仿真演示，所有策略在**同等算力预算**下微调。

两个结论都重要。

一是**孪生体的排序与真机完全一致**。五个未使用任何真实数据训练的策略（四个 VLA 加一个 LLM agent），同一份权重放到真机的未见环境、未见物体上，排序一字不变（Spearman ρ = 1.00，MMRV = 0.000）——但仿真**系统性高估**成功率。

二是九个 VLA / world-action 模型中最好的只到 **约 61%**，空间摆放、未见物体类别、旋转塞入规划三项仍然没有解决；而一个**写代码、把抓取环节交给学到的策略**的 LLM agent 拿到 **83.2%**。消融显示这 22 个百分点的领先来自 harness 的选择和语言模型的选择，不来自策略本身。

**这改变了什么**：两件事。其一，在「空间约束 + 语言条件」这类任务上，瓶颈看起来在**任务结构的组织方式**而非策略容量——端到端 VLA 目前输给一个会写代码、只把抓取外包出去的 harness。这对「继续堆数据微调」这条默认路线是个实质性质疑。其二是方法论：ρ=1.00 配上「系统性高估」意味着数字孪生的**排序信息可信、绝对数值不可信**。这是两件常被混在一起用的事，而这篇给出了把它们分开的实证依据。

同期还有一篇 [RoboSeed](https://arxiv.org/abs/2610.40026) 走的是框架路线（能力、下游训练可负担性、部署可负担性、本地验证的研究价值、复现证据五个维度），其中一条原则值得单独记住：**缺少测量时明确拒绝给出聚合分数**，并把证据缺口显式标出来。它自己也承认不完整的 serving trace 与异构协议导致无法给出总体排名——这种克制在评测论文里不常见。

## 四、长程任务：学一个进度估计器，还是显式维护一张依赖图

同一个问题今天有两种解法，适合对着读。

[ReSTEP / REMORA](https://arxiv.org/abs/2610.39125)（智元）指出：长程任务需要可靠判断执行是在**推进、停滞、倒退，还是正在从错误中恢复**，但带帧级错误标注、且真正覆盖错误恢复过程的真机数据集极少。他们开源了 ReSTEP——两个操作任务共 3,156 条 episode，带语义阶段标签和帧级错误标注。配套的 REMORA 是一个在线进度估计器，组合**循环视觉记忆**（保留执行历史以消解视觉上相似阶段的歧义）、分布式预测（表示并存的多个进度假设）与因果峰值选择（在时间上跟住一个被支持的假设），在进度准确率和时间一致性上优于 SARM 基线。值得注意的是它把记忆放在**控制回路的监控侧**，而不是外挂一个 LLM planner。

[LOGIV](https://arxiv.org/abs/2610.40016)（新加坡国立 Yang You、Ivor Tsang 等）的立论更锐：**一个动作完成了，不保证它的效果会持续**——后来的扰动可以让剩余计划仍然依赖的支撑失效。LOGIV 把验证过的计划编译成「条件-支撑边」与「资源-顺序边」构成的显式任务图，执行期持续检查这些边的物理有效性，失败后用依赖追溯决定**必须恢复什么**，续接的组合在恢复执行前先做符号验证。整个框架跑在已有 VLA / world-action 策略之上，**不加任何可训练组件**。RoboTwin V2 与 BiCoord 的 20 个双臂任务、三种执行 backbone：无扰动时平均成功率分别 +10.67 和 +15.33 个百分点；有预定义扰动时在两个基准的每个 backbone 上都优于三个改编的恢复基线。三个真机任务成功次数 12/30 → 17/30。

两者的权衡很清楚：REMORA 要训练但不要求任务有符号描述，LOGIV 不要训练但要求能写出符号前置条件。

## 五、其余四条

### Smooth Action Chunking Via Movement-Primitive Representations

[arXiv:2610.39451](https://arxiv.org/abs/2610.39451)

action chunking 已经是从 diffusion policy 到大 VLA 的共用接口，但这篇指出一个被忽略的后果：**chunk 的时间结构只被隐式地学到**，于是下发轨迹在 chunk 内和 chunk 之间都是 jerky 的，真机上表现为可见抖动和从动端速度限幅的反复饱和。

做法是把一段轨迹表示成**光滑基函数的线性组合**，光滑性由构造保证，而**策略架构、训练目标、推理流程全都不动**。同一个表示还给出 chunk 间跳变的**闭式推理时修正**：把新 chunk 的预测系数条件在「穿过上一 chunk 最后一个下发动作」这个 via-point 上，不用重训；与异步的 Real-Time Chunking 不同，这招对**一次性出 chunk 的策略也适用**。在 ACT（一次性）和 DiT（迭代式）两种 backbone、仿真加真机双臂 ALOHA 上：chunk 内 jerk 分别降**一个数量级**和 **2.4 倍**，任务成功率统计上非劣。

**这改变了什么**：chunk 之间的不连续通常被当成要靠异步推理解决的工程问题，于是容易一直往后排。这篇把它拆成两半：chunk 内的 jerk 是**表示问题**（换基函数就降一个数量级，架构不动），chunk 间的跳变有**闭式解**（条件在 via-point 上，不用重训）。两半都不需要改训练管线，所以这件事的性质从「架构改造」变成了「现在就能加的后处理」。

### ScheduleGen: Demonstration Generation via Skill Scheduling

[arXiv:2610.39429](https://arxiv.org/abs/2610.39429) · [项目页](https://schedulegen.github.io)

NVIDIA（Mandlekar、Garrett、Yuke Zhu）。双臂与人形平台周期更短但更难安全控制，因为存在多臂约束；自动演示生成能从少量源演示合成新演示来缓解数据瓶颈，**但现有算法忽略多臂约束，于是经常合成出不安全且失败的行为**——这个失败模式本身就值得记住。ScheduleGen 是一套集成的规划 + 调度算法：28 个仿真任务变体（含 7 个外部作者编写的 RoboDojo 任务，以及此前系统做不到的设定）上数据生成成功率 **79.6%**、训出的策略 **65.5%**，优于 SOTA 数据生成基线；八个真实变体上通过 zero-shot sim-to-real 与 real-to-sim-to-real 拿到 **50–80%**。把约束放进调度而不是放进后置过滤，是这篇结构上的要点。

### RoboAtom: Large-scale Atomic-Action Supervision

[arXiv:2610.40207](https://arxiv.org/abs/2610.40207)

浙大 Chunhua Shen、上海 AI Lab Junting Dong 等。细粒度动作标注能支撑技能复用和组合泛化，但机器人数据集通常只有任务级指令；而少数带子任务标签的，**格式与约定不一致，反而阻碍跨源联合训练**——这个判断是整篇工作的出发点，重点因此不在模型而在**协议**。RoboAtom-Data 给多来源的既有数据补上统一、时间对齐的原子动作标注：**145 万条轨迹、688 万个带技能标签的片段、16,882.1 小时**。管线是统一协议 + 大规模人工标注 + 在「同一有序技能序列的重复执行」之间传播标注 + 多级质检，最后一点是个便宜的放大手段。配套 RoboAtom-Bench 标准化技能识别与时间边界定位；RoboAtom-Anno 在自家与外部 WGO-Bench 上都优于所有评测过的开闭源模型。控制侧，原子动作监督配分层执行在 LIBERO-Long、LIBERO-Plus、RoboTwin 上均优于任务级基线。数据、基准、模型与构建管线都将开源。

### Proving and Improving the Platonic Representation Hypothesis with JEPAs

[HuggingFace Papers](https://huggingface.co/papers/2610.39302)

Balestriero 与 LeCun。这不是具身论文，但它改的是一件对 VLA backbone 选型有直接后果的事，所以收进来。

柏拉图表示假设猜测：不同模态上训练的模型随规模增长会收敛到同一个世界表示。这篇把猜想变成定理——只要正样本对是**同一场景的两个观测**（作者称 good views）、其余错配有界，分别在任意多个模态上训练的 JEPA 就会学到**相差一个旋转的同一表示**。第二步是关键的重新归类：**next-token prediction 是 bad views 版本的 JEPA**（它的正样本对是同一文档的两个部分），这就解释了为什么语言模型只有靠规模才能和视觉对上。

实证从 14.5 万条 caption 一直到 9.4 亿张网络图片的文本，还给出一条能在种子噪声内预测未见 run 的对齐 scaling law。两个数字最有说服力：同一语料上达到同等对齐度，good views 需要的样本**少 42 倍**；一个 **109M** 参数的 text JEPA，比他们评测过的所有语言模型（最大到 **72B**）、也比 CLIP 自己的文本编码器，都更接近 DINOv2 与 CLIP 的图像编码器。

**这改变了什么**：视觉与语言在一个多模态 backbone 里的对齐程度，通常被当成规模的函数，于是选型逻辑就是「挑能拿到的最强 VLM」。这篇给出的是另一个因果：对齐是**视图构造**的函数，规模只是 bad views 情况下的补偿手段。42 倍和「109M 打败 72B」放在一起，意思是在自有数据上认真构造「同一场景的多模态 / 多视角观测对」，回报可能远高于换一个更大的语言塔。

## 本期没进来但值得一提

- **腾讯 Hy-Nomas**（8B 扩散世界模型，文本指令与连续相机轨迹在单一生成架构里交织）。它的机制描述很具体：**动作感知因果注意力**把语义描述拆成「环境背景前缀」与「时间窗动作后缀」，跨段隔离动作文本，专门为了消除「已经做完的动作在后续分段里反复重演」这个失败模式；再加段级自暴露训练对抗自回归误差放大。没收是因为能拿到的只是论文的中文转述，不是一手判断。但「动作指令像幽灵一样跨段重演」和前面 Utility-WAM 的 future-induced negative transfer 属于同一族问题，这个对照值得记着。
- **Continuous-Action World Models (CoAWM)**（[2610.40401](https://arxiv.org/abs/2610.40401)）命题很对：跨本体**且跨执行频率**的共享潜函数空间，单个解码器接受任意 query 时刻返回末端动作。把控制频率也当成需要对齐的维度，这个角度此前少见。但摘要里一个实验数字都没有，无法判断可信度，等后续版本。
- **BURGER**（[2610.40532](https://arxiv.org/abs/2610.40532)）用「机器人画画」做 VLA 泛化基准，28,200 条演示、282 个任务，好处是数据可以靠 prompt 驱动的管线无限生成。任务域离接触密集操作较远，数据规模的结论是否可迁移存疑，但作为一个廉价的语言 grounding 与空间组合探针挺有意思。
