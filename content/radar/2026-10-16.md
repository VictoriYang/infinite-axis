## 1. InfiniHand：一个流式模型出世界坐标系的手部动作，顺带发现公开数据集三分之一的标注对不上画面

[arXiv](https://arxiv.org/abs/2609.35743) · [量子位整理](https://mp.weixin.qq.com/s?__biz=MzIzNjc1NzUzMw==&mid=2247933304&idx=3&sn=01d65c311875cab48be67fd024db8d9c) · 上海 AI Lab / 上海交大（Bo Dai、Chunhua Shen、Junting Dong 等）

从头戴相机的视频里提取三维手部动作，难点在镜头自己也在动：画面里手向右移，可能只是转了一下头。此前的做法是级联——检测器找手、手部网络估姿态、SLAM 追相机、最后对齐——每一环的抖动、漂移和尺度偏差都往后传，处理大规模视频时多套模型的协调成本也高。InfiniHand 把这些环节共享的几何上下文放进一个流式前馈模型：预训练的几何骨干从全图提特征，定位模块据此找左右手区域，重建模块再融合局部外观补手指细节；输出 MANO 参数，辅助的 2D 关键点头约束 3D 结果的投影；结合估出的相机轨迹，把各帧手部结果转到同一个世界坐标系。流式推理保留初始参考帧、近期细节特征和更早时刻的压缩记忆，后台跑稀疏束调整修长序列漂移。ARCTIC 上 PA-p 比 ViDiHand 降 21.4%，预测吞吐 11.19 FPS，约为 HaWoR 的两倍（束调整的开销另算）。

但这篇最有用的信息在数据那一节。训练集从 ARCTIC、HOT3D、EgoDex 等九个公开数据集汇集了约 5000 小时，清洗时用 Sapiens 2 预测画面里的 2D 手部关键点，和原始标注的投影比对，持续不一致的序列整段筛掉，不确定的留人工检查。**这一步去掉了 30%-40% 的候选训练数据。**

这个数字改变的是对公开第一视角数据集的默认信任度。此前拿公开 ego 数据混训，主要担心的是格式层面的事：左右手顺序、坐标定义、标注种类对不齐。这篇说明标注和画面对不上的比例远高于直觉，而且只靠一项重投影一致性检查就能筛出来。两个直接的做法变化：一是自己采的第一视角数据——不管手部真值来自手套、动捕还是别的——也应该做同样的检查，把 3D 手姿态投影回相机画面和一个独立的 2D 检测器比对，持续偏离的段落标为不可信，而不是默认动捕就是真值；二是打算混进训练的公开 ego 数据集，先过一遍这个筛再定配比，否则相当一部分算力是在教模型错的东西。

## 2. PORTAL：多模态模型的 projector 预训练只做了粗对齐，用统计量初始化就能跳过

[arXiv](https://arxiv.org/abs/2610.18598) · [GitHub](https://github.com/mlbio-epfl/PORTAL) · EPFL（Maria Brbić 组）

多模态大模型的标准训法是先用大量图文对单独训一个 projector 把视觉编码器对齐到语言模型，再联合训全模型。第一阶段到底在干什么，一直没人说清。这篇给了两个实证：只用 10%-20% 的数据训 projector 就拿回了绝大部分下游收益；在不同数据集上训出来的 projector 可以线性插值，性能基本不掉。两件事合起来说明 projector 训练只做了一次粗对齐，很多不同的 projector 都能做到同样好。

顺着这个结论，PORTAL 干脆不训：只用每个模态的特征统计量（高斯近似），在共享主子空间上算一个最优传输映射当 projector 初始化，不要配对数据、不要梯度。六个 LLM 骨干、两个视觉编码器、十六个 benchmark 上，和用 558k 图文对训出来的标准管线打平——七组设置里三组反超，其余四组平均 98%。

对具身侧的意义有两层。第一层直接：复现或改造视觉-语言-动作模型时，视觉-语言对齐的 stage-1 不值得投大预算，换视觉编码器时先试统计量初始化再直接进联合训练。第二层是推断，不是这篇的结论：VLA 里为不同机器人本体各配一个本体感知 / 动作 projector 是常见做法，默认它承载了本体特异性。这篇的线性插值检验是个便宜的实验——把两个本体各自训出的 projector 插值，如果性能不掉，说明它们也只是在做粗对齐、本体差异并没有落在 projector 里，该建到别的地方去；如果插值后崩了，才说明 projector 真的承载了本体差异。这个实验的成本几乎为零，先做再决定架构。

## 3. WEDGE：失败样本的价值不在样本本身，在于被归纳成可验证的弱点再去控制生成器

[arXiv](https://arxiv.org/abs/2610.19420) · [GitHub](https://github.com/zhangyuejoslin/WEDGE) · UNC（Mohit Bansal 组）

仿真环境能为具身 agent 批量生成训练数据，但现有的环境生成管线都在优化通用属性——真实度、多样性、任务覆盖——而不同的预训练策略是因为不同的环境原因失败的，「更多数据」不等于「这个策略需要的数据」。WEDGE 的循环是：对比成功和失败的 rollout，让 LLM 提出**可执行的弱点特征**，在诊断集上自动验证，按成功率差距选最强的那个验证过的弱点，映射到控制它的环境因子，调这些因子在策略正挣扎的难度区间里生成适配环境。

结果里有三个值得记的点。三个适配机制不同的导航 agent，弱点画像各不相同，需要的训练环境也不同。弱点条件化的适配在 ProcTHOR 上**稳定优于配平的随机生成和 hard-example 回收两种对照**，Uni-NaVid 和 Gemini 在 ProcTHOR 上适配后的收益能迁到 HM3D。迭代重诊断显示主导弱点会随策略改进而持续或转移。

任务是导航不是操作，但机制与任务类型无关，只要仿真器的任务生成参数可控就能套。它改变的是对「失败数据怎么用」的默认理解。此前自进化闭环里失败数据的用法基本是回收失败样本当 hard example 再训，关键在于采够失败；这篇的对照说 hard-example 不如弱点条件化生成——失败的价值在于被归纳成一个可验证的弱点特征，再反过来控制生成器参数。做法上的变化是：闭环不该直接把失败 episode 塞回训练集，先做「成功 vs 失败的对比诊断 → 提出环境因子假设 → 在诊断集上验证 → 按验证过的因子调生成参数」；而且每轮要重新诊断，固定一套 hard case 池会在几轮后失效，因为主导弱点会转移。

## 4. Thinking Leakage：RL 后训练的涨点，可能只是重新激活了预训练模型被压住的模式

[arXiv](https://arxiv.org/abs/2610.14270) · [GitHub](https://github.com/WenxuanZhu1103/think-leakage) · KAUST（Bernard Ghanem 组）

Qwen3 这类混合推理模型用几个模板 token 切换 THINK 和 NO-THINK 模式，流行的做法是在 NO-THINK 模式下做 RL，然后报告推理能力提升。这篇给证据说涨点的大部分是「泄漏」：RL 只是部分重新激活了原模型 THINK 模式里已有的能力，不是学到了新的推理行为。Qwen3-1.7B / 4B / 8B 上用 GRPO：准确率涨的同时回答变长、更「反思」，原模型越来越判定它像自己的 THINK 输出，内部激活向 THINK 模式偏移；放大 RL 更新会逼近 THINK 模式的准确率，但不超过。8B 上最直接的证据：把 RL 后模型的一个低维 THINK 相关激活子空间换回原模型的值，RL 收益大部分消失；反向替换能把相当一部分收益转到原模型上。机制上，advantage 加权更偏好 THINK-like 的回答，一步梯度就把模型往 THINK 状态推。

和具身没有直接接口，但它是「指标涨了但实际没变强」这类分析的一个干净范本：RL 的收益有一个来自预训练模型的隐藏天花板，不去比就看不见。对机器人策略的 RL 后训练来说，对应的做法是多加一条基线——同一个预训练策略在它最强的推理模式下（换 prompt、启用带推理的 grounding 分支、更长的动作块）能到多少。RL 后如果没超过这条线，就要怀疑只是把预训练里被模板压住的行为释放了出来。激活子空间交换是个便宜的诊断，可以直接搬过去。

## 5. LabInstruct：视频生成看起来合理，流程上是错的

[arXiv](https://arxiv.org/abs/2610.14020) · [GitHub](https://github.com/CSU-JPG/LabInstruct) · 中南大学等

自驱实验室里机器人还接不住细粒度操作和长程流程，人仍然是「AI 规划」和「物理执行」之间的接口，于是需要给人看的实验指导；视频生成现在能从一张工作区图加一句指令直接合成演示。这篇做了个 benchmark 问这些演示靠不靠谱：五个学科 204 个任务，有真实参考执行，带物体、动作、接触、状态转移的结构化标注。测八个前沿 image-to-video 模型，结论是**视觉上合理的生成频繁地在流程上是错的**，视觉真实度和作为操作指导的可靠性之间差距很大。

结论方向上和已有认知一致，是又一组证据，不改变做法。记它是因为它把一件事量化了：把视频生成模型拿来当机器人规划器或世界模型评估器时，VBench 那类视觉指标和过程正确性是脱钩的，评测得有接触和状态转移层面的结构标注才测得出来。
