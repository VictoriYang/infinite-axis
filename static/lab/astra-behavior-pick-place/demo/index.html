01

理解任务

先定义什么才算成功

任务定义：将一个地面饮料罐放到低茶几上并松手。在 BEHAVIOR-1K 仿真场景中，将任务拆分为抓取、携物移动、放置与松手四个阶段，并分别检查执行进展。

通过 SSH 检查，确认服务器已有 OmniGibson、R1Pro、CuRobo 运动规划器和空闲 GPU。选择通过底盘与机械臂控制器执行的运动规划，让机器人实际完成抓放动作。

目标对象为地面饮料罐，目标位置为低茶几。完成与否由物体在桌上的状态和夹爪持物状态共同判定，而不是仅凭动作指令已发送或程序已结束。

预先确定的成功条件
初始 OnTop 为假 → 执行后 OnTop 为真 → 罐子不在任何夹爪中。
02

初次尝试

控制执行与证据记录并行

复用现有 StarterSemanticActionPrimitives，由 CuRobo 规划机械臂轨迹，底盘使用 A* 路径与位置伺服。另加审计包装器，逐步记录控制指令，并定期记录关节、底盘位置、罐子位置、抓持状态和任务谓词。

实验开始前将机器人出生位置设到客厅。抓持使用仿真的 sticky 辅助约束，配合机械臂和夹爪控制完成抓取与携物移动。

第一次执行中，机械臂伸向罐子、闭合夹爪并将罐子提离地面。随后底盘携带罐子移动。这些动作由日志、位置观测和渲染画面共同确认。

已完成的阶段
抓取成功、罐子离地、底盘发生移动；这些只说明部分进展，不等于整个任务完成。
03

失败归因

动作持续，不代表任务推进

失败发生在携物导航阶段。A* 未找到通往采样目标的路径，原有导航器退回直线尝试。底盘实际移动约 1.6 米，随后停在距目标约 24 厘米处，控制指令仍在发送。

当时的到位位置容差为 8 厘米，单次导航预算为 6,000 步。到人工中止时，共执行 3,630 步，罐子的 OnTop 仍为假，因此判为失败，并保留已有帧和轨迹。

已确认：导航没有收敛。尚未确认：具体是哪一个碰撞或几何约束导致停滞。没有进行接触诊断，因此不能断言“被茶几卡住”。

失败不是凭观感判断
最终 OnTop = false；无成功状态转换。被监控的直接位姿设置接口在执行阶段没有记录到调用。
04

调整策略

限制导航尝试，保留成功门槛

针对导航长期不收敛，在独立包装器中调整两项参数，不修改原项目。新的尝试不再长时间追求底盘精确到达某一个采样点，而是在足够接近后让机械臂规划器尝试放置。

参数 / 判定第一次第二次
底盘到位位置容差0.08 m0.28 m
单次导航最大步数6,000700
任务成功条件不变：OnTop 从假变真，且夹爪已松手

放宽的是导航到位条件，不是任务成功条件。机械臂仍需完成抓放，最终仍由物体状态判定；没有加入直接移动罐子或强制设置成功状态的操作。

这是一次策略假设，而不是已证实的因果结论
“接近后交给机械臂规划”可能比继续追求底盘精确到位更有效，需要实际执行验证。
05

成功完成

以最终状态核验结果

第二次完成 923 步控制：机器人抓起罐子，调整底盘位置，执行放置并收回机械臂。这次随机采样出了不同的导航目标，而且 A* 找到了路径。

  • OnTop(can_of_soda_113, coffee_table_koagbh_0) 从 false 变为 true。
  • 最终左右夹爪均为空，罐子已放下。
  • 执行阶段被监控的直接位姿设置接口调用数为 0。
  • 录像保留 223 帧，8 fps，约 27.9 秒；已核验完整性。

这些证据确认了本次抓放任务成功，但不能将成功完全归因于参数调整：采样目标和路径可用性也发生了变化。若要检验修改的因果作用，需要固定随机种子、初始状态并进行重复对照。

结论
通过接入、调试和编排现有规划器，完成了将一个地面饮料罐放到低茶几上并松手的任务，录像与独立状态检查结果一致。

任务完成，证据闭环
